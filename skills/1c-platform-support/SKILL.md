# 1c-platform-support — поддержка объектов и редактируемость

> Платформа определяет «можно ли править объект» через **состояние поддержки**, а не через префикс имени. Префикс — лишь эвристика. Этот скил объясняет, как это работает на самом деле.

## Главное правило: два слоя кода

| Слой | Признак | Действия |
|---|---|---|
| **Прикладной** («наш») | с префиксом проекта; `f1 = 1/2` или не на поддержке | Здесь ведётся разработка |
| **Библиотечный** (БСП и пр.) | без префикса; `f1 = 0` (на замке у поставщика) | **Не править.** Перезатрётся при обновлении. |

Перед правкой модуля **всегда** проверяй редактируемость. Эвристика по префиксу — упрощение; точный ответ — через состояние поддержки.

---

## Как платформа определяет «можно ли править»

Алгоритм по `Ext/ParentConfigurations.bin`:

```
1. Файла поддержки нет → поддержки нет          → редактирование РАЗРЕШЕНО
2. G = 1 (глобальный запрет)                     → read-only ВСЁ
3. G = 0 → проверяем f1 по uuid объекта:
     f1 = 0 (на замке) хотя бы у одного поставщика → ЗАПРЕЩЕНО
     f1 = 1/2 (редактируется/снято)              → РАЗРЕШЕНО
     uuid не найден                               → не на поддержке → РАЗРЕШЕНО
```

Где:
- **G** — глобальный флаг запрета (1 = всё read-only).
- **f1** — флаг редактирования конкретного объекта у конкретного поставщика:
  - `0` — на замке у поставщика (править нельзя).
  - `1` — редактируется с изменениями (править можно, обновление с конфликтами).
  - `2` — снято с поддержки (править можно, обновления не применятся).
- **uuid** — идентификатор объекта метаданных.

📖 [Полный алгоритм и формат ParentConfigurations.bin](https://github.com/Nikolay-Shirokov/cc-1c-skills/blob/main/docs/1c-support-state-spec.md)

## Практические следствия

### «Свой» код — это…
- Объекты с `f1 = 1/2` (редактируется/снято).
- Или объекты, вообще не на поддержке (uuid не найден в `ParentConfigurations.bin`).

### «Чужой» код (БСП) — это…
- Объекты с `f1 = 0` (на замке у поставщика 1С или другой библиотеки).
- Их правка перезатрётся при следующем обновлении.

### Быстрая проверка
1. Посмотреть префикс объекта. Своего проекта — вероятно «наш».
2. При сомнении — объект не на поддержке можно редактировать смело.
3. Точная проверка — в Конфигураторе: пиктограмма замка / свойство «Редактируется».

---

## Что НЕ делать

- **Не править БСП-объекты** (`ОбщегоНазначения`, `Пользователи`, `РаботаСФайлами`…) — они на замке у поставщика.
- **Не снимать объекты с поддержки «на всякий случай»** — обновления БСП перестанут применяться к ним.
- **Не полагаться только на префикс** — это эвристика. Точный ответ — через состояние поддержки.

- [ ] Если правлю БСП через расширение (CFE) — см. скил `1c-extensions`
- [ ] При конфликте обновления — понимал, какие мои правки затронуты
