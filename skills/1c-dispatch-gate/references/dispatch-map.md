# Карта диспетчеризации: сигнал → карточки правил

> **Индекс-маршрутизатор.** Открывается в начале каждой задачи и при самопроверке.
> Это не контент, а таблица «что я вижу/делаю → какие карточки открыть».
>
> Полная версия гейт-чек-листа из `1c-dispatch-gate/SKILL.md`. Здесь — расширенный вариант с дополнительными замечаниями и контекстом инцидентов.

## Как пользоваться

1. **Перед задачей** — **сначала** пройдите гейт-чек-лист ниже, **затем** — таблицу A.
2. **При написании кода** — заметили симптом из таблицы B — откройте указанные карточки.
3. **После написания** — прогоните по `1c-thin-triggers`.

Скилы лежат в `skills/` этого плагина (`1c-queries`, `1c-forms`, `1c-metadata` …). Карточки стандартов v8std — на `github.com/zeegin/v8std/blob/main/docs/std/NNN.md`.

## 🔴 Гейт-чек-лист (пройти ОБЯЗАТЕЛЬНО перед этапом 2 «Реализация»)

Для **каждого** утверждения, подходящего под задачу, — отметить и открыть скил.

| Условие задачи | Открыть скилы | Что проверить |
|---|---|---|
| ☐ Создаётся **новый объект** метаданных (справочник, документ, обработка, регистр, **константа**) | `1c-metadata` · `1c-security` | Случайные UUID (включая `typeId`/`valueTypeId`!), синоним ru/en, **роли** (№532), структура модуля |
| ☐ Создаётся/правится **форма** | `1c-forms` | 5 обязательных областей, бизнес-логика вне формы |
| ☐ **Правка XML** формы/объекта (`.form`/`.mdo`) вручную | `1c-metadata` | `LineNumber`, `PagesGroupExtInfo`, `<enabled>` у Page, уникальность UUID, роли (M11) |
| ☐ Есть **запись/проведение** документа или массовая запись | `1c-events-transactions` | Шаблон транзакции, блокировки, `ПроверитьЗаполнение()` |
| ☐ Есть **запросы** | `1c-queries` | Нет запроса в цикле, перечислены поля |
| ☐ **Чтение/запись данных** справочников/документов | `1c-events-transactions` · `1c-code-review` | Точечное чтение, `ЗначенияРеквизитовОбъекта` вместо `.ПолучитьОбъект()` |
| ☐ Работа с **файлами/сетью** | `1c-integration` | Только спецкаталог, таймауты, вне транзакции |
| ☐ Есть **команды формы**, модифицирующие данные | `1c-forms` | Флаг `modifiesStoredData` (Изменяет сохраняемые данные) |
| ☐ Есть **исключения/перехват** (`Попытка/Исключение`) | `1c-logging` | Логирование, не молчаливый перехват |
| ☐ Это **регламентное задание** | `1c-scheduled` | Идемпотентность, устойчивость, расписание реалистичное |

**Правило:** ни одно подходящее утверждение не должно остаться неотмеченным. Если отмечено — скил открыт и прочитан, а не просто «посмотрел по названию».

> 💡 **Универсальные грабли, которые этот гейт должен ловить:**
> - **Роли (№532)** — новый объект без ролей невидим пользователям.
> - **Чтение внутри транзакции (№783)** — частый источник блокировок.
> - **UUID в `<producedTypes>`** — забывают перегенерировать, оставляют плейсхолдеры.
> - **`modifiesStoredData`** — забывают на командах формы, модифицирующих данные.
> - **Молчаливый `Попытка/Исключение`** — глотает ошибки, превращая систему в «чёрный ящик».

## Таблица C. По симптому проблемы

| Симптом | Открыть |
|---|---|

| «Данные рассинхронизированы» | `1c-events-transactions` |
