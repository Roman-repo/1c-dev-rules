# 1c-release — Включение в релиз: состав, миграции, примечания

> Роль этапа — **РП / релиз-инженер**. Релиз группирует **принятые** задачи:
> железное правило — в релиз не входит то, у чего нет протокола «принято».
> Выход — два артефакта: **Состав релиза** и **Примечания к релизу**
> (на релиз целиком, не на задачу).

## Вход этапа

Задачи с протоколом приёмки `06` в статусе «принято» / «принято с
замечаниями» (класс D идёт ближайшим релизом — включается с пометкой).

## Процедура

1. **Отбор задач.** 🔴 Только с протоколом «принято». «Почти принято, завтра
   подпишут» — в следующий релиз: недопринятая задача в релизе бьёт по всему
   релизу (откат целиком дороже ожидания одной задачи).
   🟡 Исключение — протокол «отложено» (приёмка перенесена, см.
   `1c-external-acceptance`): при длинном цикле сборки релизные артефакты
   готовятся **черновиком** (`_releases/<версия>-draft/`) с явным статусом
   «не включять в поставку до приёмки» и записью задачи в «Отбор отклонён»;
   черновик повышается до боевого после закрытия приёмки. Черновик не висит
   бесконечно: при истечении даты пересмотра из протокола 06 РП решает —
   повысить (приёмка закрыта) либо расформировать состав, задача возвращается
   в бэклог.
2. **Зависимости и порядок.** Задачи, меняющие одно и то же (объект, право,
   миграцию), — упорядочить; конфликтующие изменения — выявить до сборки
   (по спецификациям 03: пересечение изменяемых объектов).
3. **Свод миграций.** Из секций «Изменения структуры данных» всех 03:
   суммарный список миграций, порядок запуска, кто выполняет, как проверяется.
4. **Примечания к релизу** — два адресата:
   - **пользователям** — что изменилось в работе (из критериев приёмки:
     «в мониторе появились колонки...»), без техжаргона;
   - **админам** — новые права/роли, настройки, регламентные задания,
     длительность и окно обновления, откат.
5. **Техническая сборка** — чек-лист `1c-collab` (версия, чистая ИБ, бэкап,
   поставка .cf/.cfu/.cfe, план отката); типовая конфигурация — учесть
   `1c-platform-support`.
6. **Фиксация артефактов** в каталоге релиза
   (`docs/delivery/_releases/<версия>/`).

## Антипаттерны

| Антипаттерн | Чем оплачивается |
|---|---|
| «Впишем недопринятую — она же готова на 99%» | Возврат всего релиза после обновления |
| Миграции в уме, а не списком | На боевом обновлении «забыли» одну — данные битые |
| Примечания из названий задач («TASK-142 доработка форм») | Пользователи не понимают, что изменилось, — поток обращений |
| Отбор задач по дате, а не по протоколу | Состав релиза расходится с юридической готовностью |

## Артефакты-выходы

- `release-manifest.md` — Состав релиза: задачи (ID, протокол, краткое
  пользовательское изменение), зависимости/порядок, свод миграций.
- `release-notes.md` — Примечания: для пользователей и для админов.

Шаблоны (оба артефакта) — `references/release-manifest-template.md`.

## Мини-чек-лист (DoD этапа)

- [ ] Каждая задача в составе имеет протокол «принято» (ссылка на 06)
- [ ] Конфликты изменяемых объектов (по 03) проверены; порядок задан
- [ ] Свод миграций полон (из всех 03): порядок, исполнитель, проверка
- [ ] Примечания: для пользователей (язык задач) и для админов (права/настройки/откат)
- [ ] Технический чек-лист 1c-collab пройден (версия, бэкап, откат)

## Детали (читать по необходимости)

- `references/release-full.md` — регламент отбора, разрешение конфликтов спецификаций, содержание примечаний, связь с 1c-collab / 1c-platform-support
- `references/release-manifest-template.md` — шаблоны release-manifest.md и release-notes.md
