# 1c-external-acceptance — Внешняя приёмка: по критериям, не по вкусу

> Роль этапа — **приёмщик** (тот, кто формулировал задачу: инициатор).
> Приёмка идёт **по матрице критериев приёмки** (`04-acceptance-criteria.md`),
> строка за строкой: ✅/❌, а не «нравится/не нравится». Выход —
> **Протокол приёмки**; при возврате — **Лист возврата** с классом каждого
> замечания.

## Вход этапа

- Отчёт внутренней приёмки (`05`) без красных строк; отклонения согласованы.
- Матрица критериев приёмки (`04`) со статусами внутренней приёмки.

## Процедура

1. **Демонстрация по матрице 04** — каждый критерий: что обещано (формулировка
   строки) → что показывается. Приёмщик подтверждает ✅ или фиксирует ❌;
   результат заносится в колонку «Статус 06» (подтверждает/оспаривает статус
   05) и в таблицу протокола; при «Отложено» — ⏳.
2. **Замечания** — формулировка словами приёмщика (цитата) + класс:

| Класс | Суть | Куда |
|---|---|---|
| **A** | Работает не по сценарию/спецификации — дефект разработки | Этап «Разработка» |
| **B** | Сценарий/спецификация неверны или неполны; поняли задачу не так | Этап «Проектирование» (обновить 02/03/04 → доработка затронутого) |
| **C** | Новое требование, вне рамок карточки (01) | 🔴 **Не возврат** — новая задача; в протоколе «вынесено в задачу \<ID\>» |
| **D** | Косметика: тексты, подписи, опечатки | Этап «Разработка», быстрый цикл |

3. **Решение**: принято (нет блокирующих ❌) / возврат (лист возврата 06a) /
   отложено (приёмщик не может выполнить проверку — нет среды/живой базы).
4. **Фиксация**: протокол `06-acceptance-protocol.md`; при возврате —
   `06a-rework-list.md` (каждое замечание: номер, цитата, класс, целевой
   этап, что сделать).

## Ключевые правила

- 🔴 **«Возврат ≠ расширение рамок».** Замечание вне рамок карточки — класс C.
  Возврат классом C размывает DoD-гейты: задача перестаёт заканчиваться.
- 🔴 **Класс — это этап, где ошиблись**, а не где теперь работать: правильный
  сценарий реализован неверно → A; сценарий сам неверен → B.
- 🟡 Повторная приёмка — **по листу возврата** и изменённым строкам матрицы,
  не «вся задача с нуля». Протоколы не перезатираются: новый со ссылкой
  на предыдущий.
- 🔴 **Дважды упавший критерий — на автоматизацию.** Один и тот же критерий
  ❌ в двух раундах протокола: возврат класса A по нему закрывается
  unit/BDD-тестом, третья ручная проверка запрещена (детали —
  `1c-delivery-gate` → `references/rework-rules.md`, `1c-testing`).
- 🟡 Приёмщик не оценивает код и архитектуру — только поведение против
  критериев. Внутреннее качество — зона ревью (`1c-code-review`).
- 🟡 **«Отложено» — легальная пауза конвейера**, не решение по существу:
  приёмщик не имеет среды для проверки (живая база, стенд). В протоколе
  фиксируются причина и порядок возобновления (что подготовить, как пройти
  матрицу 04). Переход на «Релиз» запрещён до закрытия приёмки; при длинном
  цикле сборки релизные артефакты могут готовиться черновиком со статусом
  «не включять в поставку» (см. `1c-release`). Возобновлённая приёмка —
  новый протокол `.r1` со ссылкой на «отложенный».
- 🔴 **Пауза не бесконечна.** В протоколе «Отложено» обязательна **дата
  пересмотра** — по умолчанию 2 недели, иная по решению РП. Срок истёк,
  приёмка не возобновлена — РП решает судьбу задачи (расконсервация, возврат
  в бэклог, закрытие) и черновика релиза; решение фиксируется в истории
  изменений карточки 01.

## Артефакты-выходы

- `06-acceptance-protocol.md` — протокол приёмки (решение, статусы критериев,
  подписанты). Шаблон: `references/acceptance-protocol-template.md`.
- `06a-rework-list.md` — лист возврата (только при возврате; входит в шаблон
  протокола отдельной секцией — сохраняется отдельным файлом).

После «принято» — этап «Релиз» (`1c-release`). После «возврат» — целевой этап
по классу; правила возврата — `1c-delivery-gate` → `references/rework-rules.md`.

## Мини-чек-лист

- [ ] Продемонстрирован каждый критерий матрицы 04; статус подтверждён приёмщиком
- [ ] Каждое замечание: цитата + класс A/B/C/D + целевой этап
- [ ] Класс C вынесен в новую задачу (ID зафиксирован), в возврат не включён
- [ ] Решение зафиксировано; протокол подписан (кто, дата)
- [ ] При «Отложено»: причина, порядок возобновления и дата пересмотра в протоколе
- [ ] При возврате: лист возврата создан; повторная приёмка назначена по его пунктам
