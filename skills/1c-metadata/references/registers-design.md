# Практика: Проектирование регистров

> Правила проектирования регистров 1С: измерения, ресурсы, реквизиты, периодичность, индексы, остатки vs обороты, проведение / перепроведение / восстановление последовательности.
> Адаптировано из [`registers-design.md`](https://github.com/comol/ai_rules_1c/blob/main/content/rules/registers-design.md) репозитория `ai_rules_1c`.

## Когда применять

При создании или реструктуризации регистра сведений/накопления — до запуска навыка работы с метаданными. Ошибки здесь дороги в исправлении: регистр обычно завязан в проведение, RLS и отчёты.

---

## 1. Выбор типа регистра

| Тип регистра | Использовать когда | Избегать когда |
|---|---|---|
| **РегистрСведений** (информационный) | Произвольные табличные данные, индексированные по измерениям, с опциональной периодичностью. Настройки, соответствия, кэш, исторические значения атрибутов, статусы обменов. | Данные — **дельта**, которая суммируется как остатки/обороты → использовать накопления. |
| **РегистрНакопления (Остатки)** | Остатки на точку времени (запас, долг, распределение). Отвечает на «сколько есть сейчас / на дату X». | Данные — только оборот по периодам, никогда как остаток. |
| **РегистрНакопления (Обороты)** | Оборот по периодам, который никогда не запрашивается как остаток (продажи, трафик). | Реален вопрос остатка — потеря остатков потом стоит полного редизайна. |
| **РегистрБухгалтерии** | Двойная запись с планом счетов. | Абстракция «двойной записи» притянута искусственно → накопление. |
| **РегистрРасчета** | Зарплата / перерасчёт период-база с зависимостями. | Всё, что не зарплата/перерасчёт. |

Ментальная модель по умолчанию: *«может ли пользователь спросить остаток на дату?»* → накопление. *«Это просто типизированный поиск?»* → сведений. Не начинайте с бухгалтерского/расчётного рефлекторно.

---

## 2. Измерения

- **Кардинальность — прежде всего.** Высококардиональные, узкофильтрующие измерения — первыми (`Контрагент`, `Договор`, `Номенклатура`); низкокардинальные (`Организация`, `Подразделение`) — после. Порядок влияет на использование индексов при запросах к ВТ.
- **Стабильная идентичность, не свободный текст.** Измерения — ссылочного типа (`СправочникСсылка.X`, `ДокументСсылка.X`, `Перечисление.X`, `Дата` для периодических). Строки или числовые коды как измерения — антипаттерн: данные ветвятся на каждой опечатке.
- **Периодичность.** Выбирайте самую грубую периодичность, отвечающую бизнес-вопросу: `НеПериодический` (константы, соответствия), `ВПределахСекунды` (движения по умолчанию), `ВПределахДня` (курсы, логи статусов), `ВПределахМесяца`/`Год` (планирование). Более мелкая — раздувает таблицу и тормозит всё.
- **`Ведущее`** — ставить на измерение, при удалении которого должна каскадно удалиться запись регистра. **Не ставить** по умолчанию — большинство измерений не ведущие.

📖 Стандарт: [№477](https://github.com/zeegin/v8std/blob/main/docs/std/477.md) Самодостаточность регистров

---

## 3. Ресурсы

- **Ресурсы — числовые/количественные.** Для накопления — **обязательно** суммируемые (`Количество`, `Сумма`, `КоличествоСтрок`). Для сведений — любой тип, но остаётся «значение на этом ключе измерений».
- **Один ресурс — одна единица.** Смешивать `Сумму` (в разных валютах) в один ресурс — ловушка. Либо разнесите по ресурсам на валюту, либо вынесите валюту в измерение.
- **Отрицательные значения.** Для накопления — допустимы и осмысленны (возвраты, списания). Для сведений — обычно code smell, кроме явно знаковых сумм.

---

## 4. Реквизиты

- Реквизиты — неотображаемые, неагрегируемые данные, путешествующие с записью (`Комментарий`, `НомерЗаказа`). По умолчанию не индексируются; **не** фильтровать запросы по реквизитам в горячих путях.
- Если repeatedly фильтруете по реквизиту — повышайте его до измерения.

---

## 5. Индексирование

- Помечайте измерения как `Индексировать` только когда они участвуют в запросах/параметрах ВТ, **не** включающих все предшествующие измерения. Первое измерение не требует явного индекса — платформа строит его сама.
- Для регистров сведений, используемых как поиск по неполному набору измерений — помечайте именно эти измерения как `Индексировать`.
- **Не** «индексировать всё на всякий случай» — каждый индекс замедляет запись.

📖 Стандарт: [№791](https://github.com/zeegin/v8std/blob/main/docs/std/791.md) Дополнительные индексы

---

## 6. Подчинение регистратору

- **`Подчинение регистратору` — по умолчанию** для накопления — регистратор заполняется движениями документа через `ОбработкаПроведения`.
- **`Независимый`** (без регистратора) — для данных без документа-источника (настройки, соответствия, текущие значения).
- Смешанный режим доступа для регистра сведений (`Независимый` с регистратором) — изредка полезен для логов статусов; трактовать как продвинутое решение и документировать.

---

## 7. Остатки, обороты, срезы

Когда у регистра есть остатки, платформа открывает виртуальные таблицы:

| Таблица | Назначение |
|---|---|
| `Остатки(&Период, Условие)` | Остаток на `&Период` по фильтру |
| `Обороты(&Нач, &Кон, …, Условие)` | Оборот за период |
| `ОстаткиИОбороты(...)` | Начальный остаток + оборот + конечный в одном вызове |
| `СрезПервых(&Период, Условие)` (инфо) | Первая запись на/после даты |
| `СрезПоследних(&Период, Условие)` (инфо) | Последняя запись на/до даты |

🔴 **Фильтровать ВТ через параметры, не через `ГДЕ` после вызова** — жёсткое правило (`anti-patterns.md §4`). Фильтр в параметре проталкивается в движок и использует индексы; фильтр в `ГДЕ` читает всю ВТ сначала.

📖 Стандарт: [№733](https://github.com/zeegin/v8std/blob/main/docs/std/733.md) Эффективное обращение к ВТ

## 8. Проведение / перепроведение

- **`ОбработкаПроведения`** — в модуле объекта документа. Внутри: сначала блокировка, потом чтение, потом запись ([locks-transactions.md](./locks-transactions.md)). Не вызывать диалоги, длительные операции, внешние сервисы.
- **`Движения.X.Записывать = Истина`** — управляет, запишет ли платформа табличную часть в регистр при коммите. Установить один раз; не тогглить в цикле.
- **Не модифицировать движения вне `ОбработкаПроведения` / `ОбработкаУдаленияПроведения`.** Прямая манипуляция `Движения.X` из внешнего кода (обработки) обходит логику последовательностей и создаёт несогласованные данные.
- **Перепроведение** — для массовых операций использовать `Документы.X.Выбрать()` + `Записать(РежимЗаписиДокумента.Проведение)` в цикле «транзакция на документ» с явной отменой при ошибках.
- **`Последовательности`** — когда порядок проведения важен между документами (отгрузка до оплаты), настройте `Последовательность`, не полагайтесь на порядок вставки.

📖 Стандарт: [№450](https://github.com/zeegin/v8std/blob/main/docs/std/450.md) Порядок записи движений

---

## 9. Запросы к регистрам

- **Всегда используйте виртуальные таблицы** для вопросов остатков/оборотов. Не сворачивайте своё агрегирование по физической таблице.
- **Индексируйте фильтры по измерениям в метаданных**, не в BSL.
- **`ВЫБРАТЬ ПЕРВЫЕ 1 ... УПОРЯДОЧИТЬ ПО ... УБЫВ`** как паттерн «последнее значение» — допустим для непериодического регистра сведений; для периодических используйте `СрезПоследних`.
- **Агрегаты**. Для накопления `ВклАгрегаты` и `АгрегатыЭтоПлоский` могут уже ускорить запрос; не отключайте агрегаты без измерений.

---

## 10. RLS

- Ограничения доступа к регистрам следуют тому же RLS-паттерну, что и справочники/документы.
- Для регистров, объединяющих несколько типовых объектов через измерения, шаблон ограничения может стать длинным — выносите повторяющиеся `И`-предикаты в переиспользуемый через подсистему управления доступом БСП.
- Тестируйте ограничение с ролью не-администратора перед вливанием — роль-администратор обходит RLS и скрывает баги.

---

## Чек-лист проектирования регистра

- [ ] Тип регистра выбран по ментальной модели (остаток → накопление, поиск → сведений)
- [ ] Высококардинальные измерения — первыми
- [ ] Измерения ссылочного типа, не строки
- [ ] Периодичность — самая грубая из отвечающих бизнесу
- [ ] Ресурсы суммируемые (для накопления), по одной единице на ресурс
- [ ] `Индексировать` — только где нужно, не «на всякий случай»
- [ ] `Ведущее` — осознанно, не по умолчанию
- [ ] Движения только через `ОбработкаПроведения`, не из внешнего кода
