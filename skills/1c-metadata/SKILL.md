# 1c-metadata — метаданные, XML, скелеты модулей, регистры

> Создание и правка объектов метаданных 1С. Самые частые грабли — при ручной правке XML и создании новых объектов.

## 🔴 Критичные правила при создании метаданных

### №532 — Роли для новых объектов
Каждый новый объект метаданных (справочник, документ, регистр, **константа**) и каждое новое поле должны быть включены **минимум в одну роль**.

**Проверка:**
```bash
grep -rl "Constant.<Префикс>Имя\|InformationRegister.<Префикс>Имя\|Catalog.<Префикс>Имя" Roles/
```
Должен вернуть ≥1 файл (обычно роль базовых прав + роль администратора).

Без ролей объект **невидим** стандартным пользователям.

### №474 — Имя, синоним, комментарий
У каждого объекта метаданных заполнены все три:
- **Имя** — для кода, без `ё`, CamelCase, с префиксом проекта.
- **Синоним** — для пользователя, на русском (+ en/es при необходимости).
- **Комментарий** — краткое назначение, для нетривиальных объектов.

### №550 — Имена объектов
- Справочники и регистры — во **множественном** числе (`Товары`, `Контрагенты`).
- Документы — в **единственном** (`ПоступлениеТоваровУслуг`).
- С префиксом проекта.

### №469 — Общие модули
Серверный/клиентский/глобальный — флаги контекста осмысленны. Не «универсальный модуль всего».

## 🔴 UUID при создании — только случайные (правило 12 AGENTS.md)

При создании нового объекта метаданных (`.mdo`/`.form`) генерируйте **каждый** UUID заново (`uuidgen | tr 'A-Z' 'a-z'`), а **не** плейсхолдерами вида `a1b2c3d4-…`.

**Это касается ВСЕХ UUID в файле**:
- `uuid` корневого объекта
- **`typeId`/`valueTypeId` внутри `<producedTypes>`** — частая ошибка: их воспринимают как «технические» и вставляют плейсхолдеры
- UUID подобъектов: `attributes`, `forms`, `templates`, `tabularSections`, `commands`, `dimensions`, `resources`

**Проверка после создания:**
```bash
# дубликаты внутри файла (должно быть 0)
grep -oE '(uuid|typeId|valueTypeId)="[0-9a-f-]+"' Объект.mdo | sort | uniq -d
# дубликат по всему проекту
grep -rn "<новый uuid>" <путь к src>
# 🟡 сверка ожидаемого количества: uniq -d выше ловит ДУБЛИ, но НЕ ловит ПРОПУСКИ
# (UUID мог не попасть в файл). Посчитайте сколько UUID сгенерировали, и для каждого
# проверьте, что он присутствует ровно 1 раз:
для каждого UUID: grep -c "$UUID" Объект.mdo  # должно дать 1
```

## 🟡 Образец может быть с изъяном

При копировании структуры с существующего объекта («по образцу») — **не доверяйте образцу как эталону**. Часто недавно созданные объекты не доведены до конца:

- **нет ролей** (№532) — объект невидим стандартным пользователям;
- **не включён в подсистему** — нет кнопки в интерфейсе;
- **не зарегистрирован в `Configuration.mdo`** — не подгрузится при загрузке конфигурации;
- **нарушает стандарты** (бизнес-логика в форме, модальные вызовы и т.п.).

Копирование переносит эти упущения. **Проверяйте новый объект по чек-листу ниже, а не по образцу.** Образец — это паттерн структуры (как расположить реквизиты, как назвать области), а не эталон полноты.

## 🔴 Грабли ручной правки XML (`.mdo`/`.form`)

### №1 — `LineNumber` в табличных частях — НЕ добавлять
Платформа добавляет его автоматически; явная копия вызывает ошибку загрузки или дублирование.

### №2 — `PagesGroupExtInfo` — с буквой «s»
Не `PageGroupExtInfo`. Опечатка **молча ломает форму**.

### №3 — Элемент `Page` — обязательно `<enabled>true</enabled>`
Без него Конфигуратор считает страницу отключённой.

### №4 — UID/UUID глобально уникальны
Не копируйте существующие. Не используйте плейсхолдеры.

Подробности и проверки §6 — `references/metadata-xml.md`.

## Структура модулей (скелеты)

### Общий модуль — 3 области
```bsl
#Область ПрограммныйИнтерфейс
#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
#КонецОбласти
```

### Модуль объекта/менеджера — обёрнут в `#Если`
```bsl
#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда

#Область ПрограммныйИнтерфейс
#КонецОбласти

#Область ОбработчикиСобытий
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
#КонецОбласти

#КонецЕсли
```

🔴 Внешний блок `#Если Сервер…` — **обязателен** для модулей объекта/менеджера.

### Модуль формы — 5 обязательных областей
`ОбработчикиСобытийФормы` → `ОбработчикиСобытийЭлементовШапкиФормы` → `ОбработчикиСобытийЭлементовТаблицыФормы<Имя>` → `ОбработчикиКомандФормы` → `СлужебныеПроцедурыИФункции`. Все 5 — **даже пустые**.

Полные скелеты — `references/module-templates.md`.

## Регистры — ключевые свойства

При создании регистра осознанно выберите:
- **Тип** (сведений / накопления: остатки / обороты / бухгалтерский / расчёта).
- **`writeMode`** (`Independent` / `RecorderSubordinate`).
- **`informationRegisterPeriodicity`** (`Nonperiodic` / `RecorderPosition` / день / месяц…).
- **`editType`** (`InDialog` / `Directly`).
- Измерения с `mainFilter` для отбора.
- Индексы под ожидаемые условия `ГДЕ`.

Подробности — `references/registers-design.md`.

## Мини-чек-лист по метаданным

- [ ] Новый объект включён минимум в одну роль (№532)
- [ ] Имя/синоним/комментарий заполнены, без `ё`, с префиксом проекта (№474)
- [ ] Общие модули с осмысленным именем и правильными флагами контекста (№469)
- [ ] Блоки функциональности — через ФО, не через константы-флаги (№470)
- [ ] Предопределённые — через механизм предопределённых (№697)
- [ ] Нет модальных окон / синхронных вызовов (№703)
- [ ] UUID случайные, включая `typeId`/`valueTypeId` в `<producedTypes>`
- [ ] В `.mdo` нет `LineNumber` в `standardAttributes`
- [ ] Структура модуля: 3 области (общий) / 5 областей (форма с ТЧ) / 4 области (форма без ТЧ)
- [ ] 🔴 Кросс-файловая согласованность: имена реквизитов в `.mdo` ↔ `Form.form` (dataPath) ↔ `Module.bsl` (`Объект.X`) — сверить grep'ом (см. `references/metadata-xml.md` §7)
