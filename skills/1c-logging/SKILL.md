# 1c-logging — журналирование и исключения

> Молчаливый перехват ошибок превращает систему в «чёрный ящик». Каждое исключение должно логироваться или обрабатываться явно.

## 🔴 №499 — Перехват исключений в коде

При перехвате (`Попытка/Исключение`) **обязательно** логировать причину через `ЗаписьЖурналаРегистрации` или Журнал истории работы пользователя.

❌ **Неправильно:**
```bsl
Попытка
    Данные = ПолучитьДанныеНаСервере();
Исключение
    // тихо глотаем ошибку — никто не узнает
КонецПопытки;
```

✅ **Правильно:**
```bsl
Попытка
    Данные = ПолучитьДанныеНаСервере();
Исключение
    ЗаписьЖурналаРегистрации(
        "<Префикс>ИмяМодуля", УровеньЖурналаРегистрации.Ошибка, , ,
        ОписаниеОшибки());
    Данные = Неопределено;
КонецПопытки;
```

## 🔴 №790 — Вызов исключений

Исключение — для нештатных ситуаций, не для управления потоком. Сообщение — понятное пользователю/разработчику, без технического мусора.

❌ `ВызватьИсключение "err-1";`
✅ `ВызватьИсключение НСтр("ru = 'Не удалось получить данные. Проверьте подключение к БД.'");`

## 🟡 №498 — Использование Журнала регистрации

ЖР — для технических событий (ошибки, важные действия ИБ). Каждая запись с осмысленным именем, комментарием, уровнем.

Имя события — через точку: `<Префикс>ИмяМодуля.Событие` (например, `<Префикс>Рассылка.Ошибка`).

## 🟡 №497 — История работы пользователя

Пользовательские действия (проведение, отмена, удаление, особые операции) — в Журнал истории работы пользователя (`ИсторияРаботыПользователя.Добавить(...)` из БСП). Это видит администратор в удобном виде.

## Шаблон события ЖР (структурированно)

```bsl
ЗаписьЖурналаРегистрации(
    "<Префикс>ИмяМодуля.Событие",
    УровеньЖурналаРегистрации.Ошибка,
    Метаданные(), ,
    НСтр("ru = 'Не удалось выполнить операцию.'"),
    ДанныеОшибки);  // Структура с контекстом
```

Используйте структурированные данные (`Структура`) и `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`, не `КраткоеПредставлениеОшибки`.

## Мини-чек-лист по журналированию

- [ ] Исключения логируются, нет «тихого» перехвата (№499)
- [ ] Вызовы исключений с понятным локализованным текстом (№790)
- [ ] Технические события — в ЖР с осмысленным именем и уровнем (№498)
- [ ] Пользовательские действия — в историю работы (№497)
- [ ] В РЗ ошибки логируются, РЗ не «падает» молча
- [ ] Имя события ЖР — через точку (`<Префикс>Модуль.Событие`)
- [ ] Структурированные данные в ЖР (Структура + `ПодробноеПредставлениеОшибки`)
