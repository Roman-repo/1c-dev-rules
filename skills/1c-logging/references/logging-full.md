## №499 — Перехват исключений в коде

**Критичность:** 🔴 Блокирующее

**Суть:** При перехвате исключения (`Попытка/Исключение`) **обязательно** логировать причину. Молчаливый перехват скрывает ошибки и превращает систему в «чёрный ящик». Используйте `ЗаписьЖурналаРегистрации` или Журнал истории работы пользователя.

❌ **Неправильно:**
```bsl
Попытка
    Данные = ПолучитьДанныеНаСервере();
Исключение
    // тихо глотаем ошибку — никто не узнает
КонецПопытки;
```

✅ **Правильно:**
```bsl
Попытка
    Данные = ПолучитьДанныеНаСервере();
Исключение
    ЗаписьЖурналаРегистрации(
        "ЗагрузкаДанных", УровеньЖурналаРегистрации.Ошибка, , ,
        ОписаниеОшибки());
    Данные = Неопределено;
КонецПопытки;
```

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/499.md)
См. также: №790

## №790 — Вызов исключений в коде

**Критичность:** 🔴 Блокирующее

**Суть:** Исключение — для нештатных ситуаций, не для управления потоком выполнения. При вызове исключения сообщение должно быть понятным пользователю/разработчику, без технического мусора.

❌ **Неправильно:**
```bsl
Если Данные = Неопределено Тогда
    ВызватьИсключение "err-1";   // что это значит?
КонецЕсли;
```

✅ **Правильно:**
```bsl
Если Данные = Неопределено Тогда
    ВызватьИсключение НСтр(
        "ru = 'Не удалось получить данные. Проверьте подключение к БД.'");
КонецЕсли;
```

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/790.md)

## №498 — Использование Журнала регистрации

**Критичность:** 🟡 Важно

**Суть:** Журнал регистрации — для технических событий (ошибки, важные действия ИБ). Не для пользовательских действий (для этого — Журнал истории работы пользователя). Каждая запись с осмысленным именем, комментарием, уровнем.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/498.md)

## №497 — Запись событий в историю работы пользователя

**Критичность:** 🟡 Важно

**Суть:** Пользовательские действия (проведение, отмена, удаление, особые операции) — в Журнал истории работы пользователя (`ИсторияРаботыПользователя.Добавить(...)` из БСП). Это видит администратор в удобном виде.

## Мини-чек-лист по журналированию

- [ ] Исключения логируются, нет «тихого» перехвата (№499)
- [ ] Вызовы исключений с понятным текстом (№790)
- [ ] Технические события — в ЖР (№498), пользовательские — в историю работы (№497)
- [ ] В регламентных заданиях ошибки логируются и задание не «падает» молча
