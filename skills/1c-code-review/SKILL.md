# 1c-code-review — чек-лист код-ревью

> Процедура проверки кода по стандартам v8std и правилам проекта. Применяется к MR/PR перед вливанием.

## Как пользоваться

1. Определите **тип изменения** в MR (какие объекты затронуты — см. таблицы ниже).
2. Откройте релевантные секции.
3. Пройдитесь по пунктам. Каждый пункт ссылается на стандарт — если сомневаетесь, открывайте первоисточник.
4. 🔴-пункты — блокирующие (MR не вливается без исправления). 🟡 — важные. 🟢 — рекомендации.

> Подробные карточки с примерами «неправильно/правильно» — в тематических скилах (`1c-queries`, `1c-forms`, `1c-metadata`…).

## Шаблон комментария к MR

При ревью удобно группировать замечания по уровням:

```
🔴 Блокирующие (обязательно исправить):
  - [№733] В СрезПоследних нет параметра даты — module.bsl:142
  - [№436] Запрос в цикле — module.bsl:88
  - [№532] Новый объект без ролей — Catalogs/<Имя>/

🟡 Важно (нужно обсудить):
  - [№636] Функция контекстная, хотя форма не нужна — module.bsl:55

🟢 Рекомендации (на усмотрение автора):
  - [№400] Сообщить → СообщитьПользователю с привязкой к полю
```

## Исключения

Любое отступление от стандарта допустимо, если:
1. Есть техническое обоснование в комментарии у кода;
2. Согласовано на ревью;
3. Зафиксировано (например, в `docs/perf-reports/` если причина — производительность).
