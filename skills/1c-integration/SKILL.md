# 1c-integration — интеграция, обмен, файлы

> Любое обращение к внешнему ресурсу — с таймаутом и вне транзакции. Зависший сервис не должен заморозить сеанс 1С.

## 🔴 №748 — Таймауты при работе с внешними ресурсами

Любое обращение к внешнему ресурсу (HTTP, COM, файловая система, БД через ODBC) **обязательно** с таймаутом.

❌ `HTTPСоединение = Новый HTTPСоединение("api.example.com", 80);` — нет таймаута, зависнет навсегда
✅ `HTTPСоединение = Новый HTTPСоединение("api.example.com", 80, , , , 30);` — таймаут 30 сек (6-й параметр; 5-й — прокси)

## 🔴 №794 — Повторные попытки

Сетевые операции могут кратковременно отказать. Реализуйте повторные попытки с экспоненциальной задержкой. Не более 3–5 попыток.

## 🔴 Внешние вызовы — ВНЕ транзакции

`HTTPСоединение` / `ОтправитьПочту` / внешние вызовы в `ОбработкаПроведения` — вынести за транзакцию. Транзакция с внешним вызовом держит блокировки всё время ожидания сети (№783).

## 🔴 Файловые операции — только в спецкаталоге

`ЗначениеВФайл(...)`, чтение/запись файлов — только через `КаталогВременныхФайлов()` или `НайтиФайлы(...)`. Не пишите в произвольные пути — Linux-сервера это не поддержат. Временные файлы — удаляйте после использования.

❌ `Путь = "C:\Temp\data.xml";` — абсолютный путь, не переносимо
✅ `Путь = КаталогВременныхФайлов() + "data.xml";`

## 🟡 Логирование интеграции

Каждый внешний запрос и ответ логируйте (уровень `Информация` или `Отладка`). При ошибке — уровень `Ошибка` с контекстом (URL, код ответа, тело).

## 🟡 Идемпотентность обмена

Повторный обмен теми же данными не должен ломать результат (дубли/перезапись). Используйте уникальные идентификаторы сообщений и проверяйте «уже обработано».

## 🔴 Аутентификация и секреты в API

Секреты — НЕ в коде, НЕ в открытых константах, НЕ в URL. Хранить в безопасном хранилище БСП, читать только на сервере, в логах маскировать. OAuth 2.0 client credentials: токен кэшировать до `expires_in`, 401 → обновить → один повтор. Подробно: `references/integration-auth.md`.

## 🟡 Обмен между конфигурациями

Между 1С — EnterpriseData (№771), не самописная сериализация; различие моделей — правила конвертации КД 3.1; планы обмена — с учётом отборов узлов (№701). Грабли: дубли при сопоставлении, GUID-рассинхрон, обмен в транзакции пользователя. Подробно: `references/exchange-edm.md`.

## Шаблон HTTP-запроса с таймаутом и логированием

```bsl
Попытка
    Соединение = Новый HTTPСоединение("api.example.com", 443, , , , 30, Новый ЗащищенноеСоединениеOpenSSL);
    Запрос = Новый HTTPЗапрос("/endpoint");
    Ответ = Соединение.Получить(Запрос);

    Если Ответ.КодСостояния >= 400 Тогда
        ЗаписьЖурналаРегистрации(...Ошибка..., "HTTP " + Ответ.КодСостояния);
        ВызватьИсключение НСтр("ru = 'Сервис вернул ошибку.'");
    КонецЕсли;
Исключение
    ЗаписьЖурналаРегистрации(...Ошибка..., ОписаниеОшибки());
    ВызватьИсключение;
КонецПопытки;
```

## Мини-чек-лист по интеграции

- [ ] Внешние вызовы — с таймаутом (№748)
- [ ] Сетевые операции — с повторными попытками (№794)
- [ ] Внешние вызовы вынесены за транзакцию (№783)
- [ ] Файловые операции — в `КаталогВременныхФайлов()` (Linux-совместимость)
- [ ] Временные файлы удаляются
- [ ] Запросы и ответы логируются (без секретов в логах)
- [ ] Обмен идемпотентный
- [ ] Секреты — в безопасном хранилище, не в коде/URL; токен кэшируется, 401 обработан
- [ ] Между конфигурациями 1С — EnterpriseData (№771), не самописная сериализация
