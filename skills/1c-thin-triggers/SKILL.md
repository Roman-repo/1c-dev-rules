# 1c-thin-triggers — чек-лист самопроверки

> Короткий набор признаков в коде, которые **легко проскочить «по памяти»**.
> Проходить по этому списку **после написания кода**, построчно.

Это **не** правила — это *симптомы*, на которые надо обратить внимание и открыть соответствующий тематический скил. Список компактный намеренно: проверка должна занимать секунды, а не минуты.

## Как пользоваться

После написания/правки кода — прогоните по этому чек-листу. Для каждого найденного триггера — откройте указанный скил (`1c-queries`, `1c-events-transactions`, `1c-metadata`…) и сверьтесь.

## Запросы

| Триггер в коде | Что проверить | Скил |
|---|---|---|
| `СрезПоследних( , )` / `Остатки( , )` — ВТ вызвана без параметров | Параметры даты и отбора обязательны | `1c-queries` |
| `ЛЕВОЕ СОЕДИНЕНИЕ ... СрезПоследних` / `ЛЕВОЕ СОЕДИНЕНИЕ (ВЫБРАТЬ...)` | Соединение с ВТ/подзапросом напрямую — вынести во временную таблицу | `1c-queries` |
| `.Ссылка.` / `.Регистратор.` в тексте запроса | Обращение через точку — неявное соединение | `1c-queries` |
| `НЕ ... В (ВЫБРАТЬ ...)` | Анти-соединение через подзапрос — заменить на `ЛЕВОЕ СОЕДИНЕНИЕ + ЕСТЬ NULL` | `1c-queries` |
| `ВЫБРАТЬ *` | Перечислить нужные поля | `1c-queries` |
| `Запрос.Выполнить()` внутри `Для Каждого ... Цикл` | Запрос в цикле — собрать массив, один запрос | `1c-queries` |
| `УПОРЯДОЧИТЬ ПО` без явной потребности | Сортировка дорога; только если нужна | `1c-queries` |
| `ОБЪЕДИНИТЬ` (без `ВСЕ`) | Неявный DISTINCT — обычно нужен `ВСЕ` | `1c-queries` |
| `ПОДОБНО "%..."` (шаблон с лидирующим `%`) | Индекс бесполезен — full scan | `1c-queries` |

## Код и модули

| Триггер в коде | Что проверить | Скил |
|---|---|---|
| `Сообщить(...)` | Для пользователя — `СообщитьПользователю` с привязкой к полю | `1c-ui-ux` |
| `&НаСервере` (контекстный) | Если форме не нужны данные — `&НаСервереБезКонтекста` | `1c-performance` |
| `.ПолучитьОбъект()` для чтения 1–3 полей | Точечное чтение через `ЗначенияРеквизитовОбъекта` | `1c-events-transactions` |
| `Текст = Текст + ...` в цикле | Конкатенация O(n²) — `СтрСоединить` | `1c-events-transactions` |
| `Попытка ... Исключение КонецПопытки;` без логирования | Молчаливый перехват — добавить `ЗаписьЖурналаРегистрации` | `1c-logging` |
| `ВызватьИсключение "err-1"` / технический текст | Понятный локализованный текст | `1c-logging` |
| `Выполнить(...)` / `Вычислить(...)` на сервере | С пользовательским вводом — инъекция | `1c-security` |
| Процедура без описания, но с `Экспорт` | Документировать по шаблону | `1c-events-transactions` |
| Более 5 параметров у процедуры | Использовать Структуру | `1c-events-transactions` |
| `УстановитьПривилегированныйРежим(Истина)` | Только служебные операции, с обоснованием | `1c-security` |
| Обработчик HTTP/Web-сервиса / экспортная функция ОМ с «Вызов сервера» | Серверный API — точка атаки: валидировать входные параметры (№678), проверять `ПравоДоступа(...)` перед операцией (№737) | `1c-security` |
| Буква `ё` в имени метаданного/переменной | Запрещена в именах (только в пользовательских текстах) | `1c-metadata` |

## Проведение и транзакции

| Триггер в коде | Что проверить | Скил |
|---|---|---|
| `НачалоТранзакции()` внутри `ОбработкаПроведения` | Транзакция уже открыта платформой — не вкладывать | `1c-events-transactions` |
| 🔴 **`Запрос.Выполнить()` / `.Выбрать()` / `.Выгрузить()` / `.ПолучитьОбъект()` между `НачалоТранзакции()` и `ЗафиксироватьТранзакции()`** | **Чтение данных внутри транзакции запрещено** (№783). Транзакция должна быть короткой и содержать только запись. Чтение и подготовку данных делайте **до** `НачалоТранзакции()`. ⚠ **Исключение:** в `ОбработкаПроведения` контроль остатков после `Движения.Записать()` (`Остатки(&МоментВремени,…)`) — каноничен, НЕ нарушение. | `1c-events-transactions` |
| `Движения.X.Добавить()` без `БлокировкаДанных` | Блокировать регистр перед чтением остатков | `1c-events-transactions` |
| `ВопросАсинх` / `ПоказатьЗначение` внутри транзакции | Диалоги в транзакции запрещены — держат блокировки | `1c-events-transactions` |
| `Движения.X` из внешнего кода (не `ОбработкаПроведения`) | Движения — только в обработчиках проведения | `1c-events-transactions` |
| `НаборЗаписей.Записать()` в цикле по **одной записи того же набора** | Антипаттерн №792 — пакетная запись одним вызовом. ⚠ **Не путать с записью разных записей через `СоздатьМенеджерЗаписи` в цикле** — это каноничный паттерн для регистров с параллельной записью (очереди, логи) | `1c-performance` |

## Метаданные и XML

| Триггер в правке | Что проверить | Скил |
|---|---|---|
| Правка `.form` / `.mdo` вручную | `LineNumber` в ТЧ, `PagesGroupExtInfo`, `<enabled>` у Page, уникальность UUID | `1c-metadata` |
| 🔴 UUID вида `a1b2c3d4-…` / `b2c3d4e5-…` (плейсхолдер-последовательность) | Это НЕ настоящий UUID — перегенерировать случайно (`uuidgen`). Реальные UUID выглядят как `58313ef8-e98f-48e1-8007-2f95b17a19a2` | `1c-metadata` |
| 🔴 `<producedTypes>` содержит `typeId`/`valueTypeId` | **Тоже UUID — должны быть случайными!** Частая ошибка: `uuid` корня случайный, а `typeId="a1b2c3d4-1111-…"` — плейсхолдер | `1c-metadata` |
| 🔴 Создал новый объект метаданных | Проверить дубликат UUID: `grep -oE '(uuid\|typeId\|valueTypeId)="[0-9a-f-]+"' Объект.mdo \| sort \| uniq -d` (должно быть 0 внутри файла) | `1c-metadata` |
| 🔴 Создал новый объект метаданных (любого типа, включая константу) | **Роли (№532):** `grep -rl "Object.Имя" Roles/` должен вернуть ≥1. Часто забывают — объект невидим стандартным пользователям | `1c-security` |
| 🔴 Создал/правил модуль формы | Все 5 обязательных областей присутствуют (даже пустые): `ОбработчикиСобытийФормы`, `ОбработчикиСобытийЭлементовШапкиФормы`, `ОбработчикиСобытийЭлементовТаблицыФормы<Имя>`, `ОбработчикиКомандФормы`, `СлужебныеПроцедурыИФункции` | `1c-forms` |
| Создал/правил общий модуль | От 2 областей: `ПрограммныйИнтерфейс` + `СлужебныеПроцедурыИФункции`; `СлужебныйПрограммныйИнтерфейс` — только если есть служебный экспорт (пустую НЕ создавать — `bslls:EmptyRegion`) | `1c-metadata` |
| Копирование UUID из существующего объекта | Генерировать новый, не копировать | `1c-metadata` |
| Команда формы, модифицирующая данные | Флаг `<modifiesStoredData>true</modifiesStoredData>` в `formCommands` | `1c-forms` |
| Код в модуле расширения без `&Перед`/`&После`/`&ИзменениеИКонтроль` | В заимствованном модуле — только перехватчики | `1c-extensions` |
| `&ИзменениеИКонтроль` без `ПродолжитьВызов()` | Оригинальный метод не выполнится — обязательно | `1c-extensions` |
| Новый объект без ролей | Минимум одна роль с осмысленными правами (№532) | `1c-security` |
| Новый объект без синонима | Синоним (ru/en) обязателен | `1c-metadata` |

## 🔴 Кросс-файловая согласованность (hand-edited metadata)

> При ручной правке метаданных XML (без EDT) один объект размазан по 3+ файлам: `.mdo` (определение) ↔ `Form.form` (dataPath/команды) ↔ `Module.bsl` (`Объект.X`). **Расхождения между файлами — самый частый блокер на импорте в EDT, который НЕ ловят чек-листы выше** (они проверяют каждый файл отдельно, а не связи между ними).

| Триггер | Что проверить | Как |
|---|---|---|
| 🔴 Создал/правил реквизит объекта | Имя реквизита **точно одинаково** в `.mdo` (`<name>X</name>`), `Form.form` (`<segments>Объект.X</segments>`, имя элемента, contextMenu, extendedTooltip) и `Module.bsl` (`Объект.X`) | `ИМЯ=X; grep -c "$ИМЯ" *.mdo Forms/*/Form.form Forms/*/Module.bsl` — везде > 0 |
| 🔴 Создал команду формы | Цепочка не разорвана: `Form.form` `commandName Form.Command.X` → `formCommands name=X + handler=X` → `Module.bsl` `Процедура X(Команда)` | `grep -n "Command.X\|<name>X</name>\|Процедура X" Forms/*/Form.form Forms/*/Module.bsl` |
| 🔴 Назначил обработчик события формы | `Form.form` `<handlers><event>OnCreateAtServer</event><name>ПриСозданииНаСервере</name>` → `Module.bsl` `&НаСервере Процедура ПриСозданииНаСервере` | `grep -A1 "<event>" Forms/*/Form.form` ↔ `grep "Процедура ПриСозданииНаСервере" Forms/*/Module.bsl` |
| 🔴 Установил параметр запроса `&X` | `Запрос.УстановитьПараметр("X", ...)` — имя **точно** совпадает с `&X` в тексте запроса (без орфографических вариантов вроде `Включать`/`Включая`) | `grep -oE '&[А-Яа-яЁё_]+' Forms/*/Module.bsl \| sort -u` ↔ `grep -oE 'УстановитьПараметр\("[^"]+"' Forms/*/Module.bsl \| sort -u` — списки должны совпадать |
| 🔴 Объявил dataPath в форме | Корневой сегмент dataPath есть в `<attributes>`: `Объект.X` → атрибут `Объект` с `<main>true</main>`; `X` (без префикса) → атрибут `X` | `grep -oE '<segments>[^<]+</segments>' Forms/*/Form.form` ↔ `grep -E '<name>(Объект\|X)</name>' Forms/*/Form.form` |
| 🔴 Создал новый объект | Объект добавлен в `Configuration.mdo` (`<dataProcessors>`/`<catalogs>`/...) | `grep -rln "Object.Имя" Configuration/` |
| 🔴 Создал **подписку на событие** | Цепочка handler не разорвана: `EventSubscription.mdo` `<handler>CommonModule.Модуль.Метод</handler>` → модуль существует → `Процедура Метод(...) Экспорт` в его `Module.bsl`; подписка зарегистрирована в `Configuration.mdo` (`<eventSubscriptions>`). Опечатка → событие молча уходит в несуществующий обработчик | `grep -oE '<handler>[^<]+' *.mdo` ↔ `grep "Процедура Метод" CommonModules/Модуль/Module.bsl` (или `validate-new-object.sh` — проверка X12) |
| 🔴 Создал **отчёт на СКД** (Report) | `mainDataCompositionSchema` в `.mdo` ссылается на существующий `Templates/<Имя>/Template.dcs` с `templateType=DataCompositionSchema`; шаблон объявлен в `<templates>`. Опечатка в имени шаблона / отсутствие файла схемы → отчёт падает при открытии | `grep -oE '<mainDataCompositionSchema>[^<]+' *.mdo` ↔ `ls Templates/*/Template.dcs` (или `validate-new-object.sh` — проверка X13) |
| 🔴 Параметр `&X` в запросе СКД (`Template.dcs`) | Имя параметра **точно** совпадает с `<parameter><name>` в схеме компоновки (и с пользовательской настройкой). Опечатка → тихий пустой результат или ошибка компиляции | `grep -oE '&amp;[А-Яа-я_]+' Templates/*/Template.dcs \| sort -u` ↔ `grep -oE '<name>[^<]+</name>' Templates/*/Template.dcs` (внутри `<parameter>`) |

🔴 **Типичный сценарий:** реквизит в `.mdo` назван `ВключатьПомеченныеНаУдаление`, а в `Module.bsl` написано `Объект.ВключаяПомеченныеНаУдаление` (деепричастие вместо инфинитива — визуально неразличимо, в рантайме «поле не найдено»). Ловится **только** grep-сверкой имён между файлами — прогоните `scripts/validate-new-object.sh` (см. скил `1c-metadata`).

## 🔴 Галлюцинации и соответствие API (критические триггеры)

> Этот класс ошибок **не ловится другими чек-листами**. Он про случаи, когда ИИ использует конструкцию, которая **звучит правдоподобно, но не существует** или недоступна в версии платформы.

| Триггер / ситуация | Что проверить | Как |
|---|---|---|
| Использую функцию, которая **не является 100% стандартной** платформенной (`Справочники.X.НайтиПоКоду`, `СтрНайти`, `СтрСоединить` и т.п.) | Существует ли она реально? Не выдумал ли? | `grep -rn "Функция <Имя>" src/ --include=*.bsl` — есть ли определение в проекте? |
| Имя функции звучит «по-1С-овски» (`НайтиИлиСоздать`, `ПолучитьСсылкуЭлемента`) | Это типичный паттерн **галлюцинации** — звучит правдоподобно, но не существует | Проверить `grep`'ом в проекте; если нет — либо определить, либо раскрыть через стандартные средства |
| Использую метод платформы, появившийся в новой версии (`ДокументМикс`, нативный парсер `.xlsx`, `Асинх`/`Ждать`) | Доступен ли в версии проекта? | Проверить `compatibilityMode` в `Configuration.mdo`; сверить с версией появления метода |
| Ссылаюсь на метод БСП (`ОбщегоНазначения.ИмяМетода`) | Реально ли он есть в версии БСП проекта? | `grep -rn "Функция <Имя>" src/CommonModules/ --include=*.bsl` |
| Использую метод/свойство, «помню которое» из обучающих данных | Это может быть устаревшим или из другой версии | При сомнении — проверить `grep`'ом по проекту и фиксировать версию |
| Ввожу «обёрточную» функцию без её определения | Раскрыть явно, через какие платформенные средства она реализуется | Либо определить тело, либо убрать псевдовызов |

**Красные флаги галлюцинации** (имена, которые ИИ склонен выдумывать):
- `НайтиИлиСоздать...`, `ПолучитьИлиСоздать...`
- `СоздатьНоменклатуру`, `ЗаполнитьИзСтроки` (звучит как метод БСП, но часто выдумка)
- `ОбщегоНазначения.СоздатьЭлемент` (нет такого в БСП)
- `ЗагрузитьТабличныйДокумент` (нет такого метода платформы)

| Триггер в коде | Что проверить | Скил |
|---|---|---|
| `HTTPСоединение` / внешние вызовы в `ОбработкаПроведения` | Вынести за транзакцию; таймаут (№748) | `1c-integration` · `1c-events-transactions` |
| Чтение → проверка → запись без блокировки | `БлокировкаДанных` перед read-modify-write | `1c-events-transactions` |
| `Попытка...Исключение` с продолжением как ни в чём не бывало | Явная обработка или `ВызватьИсключение`; не молчать | `1c-logging` |
| Файловые операции (`ЗначениеВФайл` и т.п.) без `КаталогВременныхФайлов()` | Только в спецкаталоге; Linux-совместимость | `1c-integration` |
| Массовая операция без транзакции на документ | Транзакция на каждый документ; отмена при ошибке | `1c-events-transactions` |

## Читаемость и сопровождаемость

| Триггер в коде | Что проверить | Скил |
|---|---|---|
| Процедура/функция длиннее 50 строк | Декомпозировать на части (кроме случаев, когда длина — тело запроса) | `1c-patterns` |
| Магическое число (кроме 0, 1, пустой даты) | Константа, перечисление, или комментарий с пояснением | `1c-events-transactions` |
| Закомментированный код без пояснения | Удалить (git помнит) или раскомментировать с обоснованием | — |
| Сложное условие `Если А И Б ИЛИ В И Не Г Тогда` без комментария | Добавить `// почему так` | — |
| Вложенность `Если` > 3 уровней | Вынести во вложенную процедуру или инвертировать условие | `1c-patterns` |
| Имя переменной `Флаг`, `Данные`, `Результат`, `Массив1` | Переименовать осмысленно | `1c-events-transactions` |
| Дублирование кода (копипаст блока > 5 строк) | Вынести в процедуру | `1c-patterns` |
| Комментарий описывает «что делает», а не «почему» | Переписать: «что» видно из кода, «почему» — из комментария | — |
