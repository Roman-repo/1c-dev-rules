## №400 / №418 / №585 — Информирование пользователя

**Критичность:** 🔴 Блокирующее

**Суть:** Сообщения пользователю — через `ОбщегоНазначенияКлиентСервер.СообщитьПользователю(...)` с привязкой к полю, **не** через `Сообщить(...)`. `Сообщить` — только для технических отладочных целей, не для пользовательских уведомлений. Каждое сообщение — с понятным текстом, локализованное (через `НСтр`).

❌ **Неправильно:**
```bsl
Сообщить("Не заполнено поле Контрагент");   // без привязки, не локализовано
```

✅ **Правильно:**
```bsl
ОбщегоНазначенияКлиентСервер.СообщитьПользователь(
    НСтр("ru = 'Не заполнен контрагент'"), , , "Контрагент");
```

📖 №400 [информирование](https://github.com/zeegin/v8std/blob/main/docs/std/400.md) · №418 [запрет Сообщить](https://github.com/zeegin/v8std/blob/main/docs/std/418.md) · №585 [сообщения](https://github.com/zeegin/v8std/blob/main/docs/std/585.md)
См. также: №761

## №524 / №660 / №687 — Стили, шрифт, цвет

**Критичность:** 🟡 Важно

**Суть:** Не задавать шрифт/цвет «вручную» в коде. Использовать элементы стиля из БСП (`ЦветТекстаСпецСлово`, `ШрифтЗаголовка` и т.д.). Это обеспечивает единообразие и адаптивность к темам.

📖 №524 [стили](https://github.com/zeegin/v8std/blob/main/docs/std/524.md) · №660 [шрифт и цвет](https://github.com/zeegin/v8std/blob/main/docs/std/660.md) · №687 [шрифты](https://github.com/zeegin/v8std/blob/main/docs/std/687.md)

## №584 — Акцентирование критичных состояний

**Критичность:** 🟡 Важно

**Суть:** Просроченные / критичные / требующие внимания строки и поля — выделять цветом через условное оформление (БСП-элемент стиля `ЦветТекстаВнимание`/`ЦветТекстаОшибка`). Не «вручную» через код.

> 💡 **Пример из проекта:** рабочее место техспециалиста выделяет критичность дефекта через условное оформление — верный подход.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/584.md)
См. также: №399

## №558 — Обновление списков при действиях пользователя

**Критичность:** 🟡 Важно

**Суть:** После интерактивного действия (проведение, отмена, удаление) связные списки должны обновляться. Но не «все сразу» — только реально зависящие от изменённого объекта. Через `ОповеститьОбИзменении` / `Оповещение`.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/558.md)

## №603 — Требования к проведению документов

**Критичность:** 🟡 Важно

**Суть:** При проведении — показывать пользователю результат (успешно / ошибка с привязкой к реквизиту). Не молчаливое «ничего не произошло». Длинные проведения — с прогрессом.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/603.md)

## №598 / №607 — Тексты и заголовки списков

**Критичность:** 🟢 Рекомендация

**Суть:** Заголовки форм и списков — в едином стиле. Список — существительное во множественном числе («Заявки на ремонт», «Наряды»). Форма элемента — в единственном («Заявка на ремонт»). Тексты — без сокращений, локализованные.

📖 №598 [тексты](https://github.com/zeegin/v8std/blob/main/docs/std/598.md) · №607 [заголовки списков](https://github.com/zeegin/v8std/blob/main/docs/std/607.md)

## №594 — Значения по умолчанию

**Критичность:** 🟢 Рекомендация

**Суть:** У полей формы — осмысленные значения по умолчанию (дата = текущая, организация = основная). Это ускоряет работу пользователя.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/594.md)

## №667 — Элементы стиля

**Критичность:** 🟡 Важно

**Суть:** Единый визуальный стиль — через элементы стиля из БСП (`ЦветТекстаСпецСлово`, `ШрифтЗаголовка`, `ЦветФонаГруппы` и т.д.). Не задавать цвета/шрифты literals (`Новый Цвет(255,0,0)`). Это обеспечивает адаптивность к темам и единообразие всех форм конфигурации.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/667.md)
См. также: №524, №660

## Мини-чек-лист по UX

- [ ] Сообщения — через `СообщитьПользователю`, не `Сообщить` (№400/418)
- [ ] Цвет/шрифт — через элементы стиля БСП (№524/660)
- [ ] Критичные состояния — через условное оформление (№584)
- [ ] Связанные списки корректно обновляются (№558)
- [ ] Заголовки в едином стиле, локализованные (№598/607)
