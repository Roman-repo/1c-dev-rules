# Практика: Паттерны расширений 1С (CFE)

> Практические шаблоны работы с конфигурациями расширений: типы перехватчиков, правила `ПродолжитьВызов`, маркеры изменений, ограничения заимствованных объектов.
> Адаптировано из [`extension-patterns.md`](https://github.com/comol/ai_rules_1c/blob/main/content/rules/extension-patterns.md) репозитория `ai_rules_1c`.

## Когда применять

При разработке расширений конфигурации (`**/Extensions/**/*.bsl`). проект — типовая конфигурация, доработки обычно идут через расширения, поэтому паттерны особенно важны.

---

## Типы перехватчиков

| Директива | Тип | Когда использовать |
|---|---|---|
| `&Перед("ИмяМетода")` | Перед | Код перед оригинальным методом |
| `&После("ИмяМетода")` | После | Код после оригинального метода |
| `&ИзменениеИКонтроль("ИмяМетода")` | ИзменениеИКонтроль | Полная замена тела метода |

### Перед / После — простые перехватчики

```bsl
&НаСервере
&Перед("ПриЗаписи")
Процедура Расш1_ПриЗаписи()
    // Выполняется ДО оригинального ПриЗаписи
КонецПроцедуры

&НаСервере
&После("ПриЗаписи")
Процедура Расш1_ПослеЗаписи()
    // Выполняется ПОСЛЕ оригинального ПриЗаписи
КонецПроцедуры
```

### ИзменениеИКонтроль — полная замена

```bsl
&НаСервере
&ИзменениеИКонтроль("ОбработкаЗаполнения")
Процедура Расш1_ОбработкаЗаполнения(ДанныеЗаполнения, СтандартнаяОбработка)
    #Удаление
    // Оригинальный код (удалён)
    #КонецУдаления

    #Вставка
    // Новый код (добавлен)
    #КонецВставки

    ПродолжитьВызов();
КонецПроцедуры
```

---

## 🔴 Правила `ПродолжитьВызов()`

| Директива | `ПродолжитьВызов()` |
|---|---|
| `&Перед` | Вызывается автоматически **после**. **Не вызывать вручную.** |
| `После` | Оригинал уже выполнен. **Не используется.** |
| `&ИзменениеИКонтроль` | **Обязателен** — без него оригинальный метод **не выполнится**. |

Частый баг: забыли `ПродолжитьВызов()` в `&ИзменениеИКонтроль` → оригинальный метод молча не выполняется.

---

## Маркеры изменений (обязательны в `&ИзменениеИКонтроль`)

| Маркер | Назначение |
|---|---|
| `#Вставка` / `#КонецВставки` | Код, добавленный расширением |
| `#Удаление` / `#КонецУдаления` | Оригинальный код, который заменён |

Маркеры сохраняют семантику diff/merge при обновлении основной конфигурации и перезаимствовании расширения.

## 🟡 Префикс методов расширения

Имена процедур/функций, вводимых расширением — со **своим префиксом** (алиасом расширения):

❌ **Неправильно** (конфликт имён с другими расширениями):
```bsl
Процедура ДополнительнаяПроверка()
```

✅ **Правильно**:
```bsl
Процедура Расш1_ДополнительнаяПроверка()   // Расш1_ — алиас расширения
```

> **Важно:** префикс расширения (`Расш1_`, `МоеРасш_`) и префикс проекта (``) — **независимы**. Префикс проекта применяется к новым объектам/реквизитам метаданных; префикс расширения — к именам процедур/функций, чтобы избежать коллизий. Алиас **не должен** содержать букву `ё`.

## Ограничения заимствованных (adopted) объектов

- Заимствованный объект (`ObjectBelonging = Adopted`) — **не копия**, а ссылка на объект основной конфигурации. При обновлении основной конфигурации автоматически перечитывается.
- **Нельзя** удалять существующие реквизиты/табличные части заимствованного объекта — они принадлежат базе.
- **Можно** добавлять свои реквизиты/табличные части (с префиксом `{PREFIX}`).
- Модули заимствованных объектов — **только перехватчики** (`&Перед`/`&После`/`&ИзменениеИКонтроль`), без прямых правок тела процедур.
- Формы заимствованных объектов — можно добавлять элементы, **нельзя** удалять существующие.

## Антипаттерны

### 🔴 Прямая правка заимствованного модуля

```bsl
// НЕПРАВИЛЬНО: правка оригинального кода прямо в модуле
Процедура ПриЗаписи()
    // изменённый код...
КонецПроцедуры

// ПРАВИЛЬНО: перехватчик
&Перед("ПриЗаписи")
Процедура Расш1_ПриЗаписи()
    // дополнительный код
КонецПроцедуры
```

### 🔴 Забытый `ПродолжитьВызов`

```bsl
// ОПАСНО: оригинальный метод не выполнится!
&ИзменениеИКонтроль("ОбработкаПроведения")
Процедура Расш1_ОбработкаПроведения(Отказ)
    // свой код...
    // ЗАБЫЛИ: ПродолжитьВызов();
КонецПроцедуры
```

## 🟢 Назначение расширения

В свойствах расширения укажите `Назначение`:

| Тип | Назначение | Когда использовать |
|---|---|---|
| Patch | `Patch` | Минимальные изменения, только перехватчики |
| Customization | `Customization` | Реквизиты, формы, модули |
| AddOn | `AddOn` | Полностью новая функциональность |

Значение влияет на поведение при обновлении и способ повторного применения расширения.

## Изменение свойств заимствованных реквизитов

Расширение может не только добавлять реквизиты, но и **изменять свойства** заимствованных
(например, расширить тип или переопределить проверку заполнения). Платформа фиксирует это
через `PropertyState` в `InternalInfo`.

### `PropertyState` — уведомление об изменении

Когда расширение меняет свойство заимствованного реквизита, в `InternalInfo` появляется
`xr:PropertyState`, указывающий затронутое свойство и состояние:

| `xr:State` | Что значит |
|---|---|
| `Notify` | Свойство изменено расширением; платформа выводит предупреждение при обновлении |
| `MultiState` | Свойство расширено (тип отличается от основной конфигурации) |

```xml
<Attribute uuid="...">
  <InternalInfo>
    <xr:PropertyState>
      <xr:Property>Type</xr:Property>
      <xr:State>Notify</xr:State>
    </xr:PropertyState>
  </InternalInfo>
  <Properties>
    <ObjectBelonging>Adopted</ObjectBelonging>
    <Name>Наценка</Name>
    <ExtendedConfigurationObject>87429f11-...</ExtendedConfigurationObject>
    <!-- изменённый тип -->
  </Properties>
</Attribute>
```

> ⚠️ При обновлении основной конфигурации изменённые свойства — точка повышенного риска:
> если поставщик поменял то же свойство, возникнет конфликт, который придётся разрешать вручную.
> Менять свойства только при реальной необходимости, и фиксировать в комментарии «почему».

## 🔴 Грабли ролей расширения (Rights.xml, платформа 8.3.27+)

### Не включайте `Enum.*` в `Rights.xml` роли расширения

Перечисления (`Enum`) в 1С — всегда публичные, явные права на них избыточны. Но главная причина не добавлять `Enum.*` в `Rights.xml` расширения — **это ломает `LoadConfigFromFiles -Extension`** на платформе 8.3.27: загрузка завершается ошибкой.

🔴 **Дополнительно:** EDT 2026.1 при определённых операциях **генерирует `Enum.*` в Rights.xml сам** — после выгрузки/импорта расширения через EDT проверьте `git diff` на наличие `Enum.` и вычищайте вручную.

❌ **Неправильно** (в `Roles/<ИмяРоли>/Rights.xml` расширения):
```xml
<right>
    <name>View</name>
    <object>Enum.Приоритеты</object>   <!-- ломает загрузку на 8.3.27 -->
    <value>true</value>
</right>
```

✅ **Правильно:** прав на перечисления не добавлять вообще.

### Двухпроходная загрузка роли расширения

Если в одном экспорте расширения вы добавляете **и новые объекты метаданных, и роли на эти объекты**, загрузка может зависать на разрешении прав (платформа пытается резолвить права на объекты, которые ещё не зарегистрированы). Обход — **двухпроходная загрузка**:

1. **Первый проход** — загрузите расширение **без** каталога `Roles/` (или с пустым).
2. **Второй проход** — загрузите расширение **полностью**, с ролями.

Это позволяет избежать зависания резолва прав. Актуально для CI/CD и пакетной загрузки; в интерактивном режиме EDT обычно разруливает сам.

## Отличия заимствованного объекта от обычного (сводная таблица)

| Аспект | Обычный (конфигурация) | Заимствованный (расширение) | Собственный (расширение) |
|---|---|---|---|
| `ObjectBelonging` | нет | `Adopted` | нет |
| `ExtendedConfigurationObject` | нет | UUID объекта конфигурации | нет |
| Набор Properties | полный | минимальный + изменённые | полный |
| InternalInfo | GeneratedType | GeneratedType + `PropertyState` (если меняли) | GeneratedType |
| Реквизиты в ChildObjects | полные | заимствованные + свои | полные |
| Модули | полные | только с декораторами перехвата (`&Перед`/`&После`/`&ИзменениеИКонтроль`) | полные |
| Формы | полные | с расширениями (`Ext/`), можно добавлять, нельзя удалять | полные |

## Чек-лист ревью расширения

- [ ] `&ИзменениеИКонтроль` содержит `ПродолжитьВызов()` (кроме случаев полной замены)
- [ ] Используются маркеры `#Вставка`/`#Удаление`
- [ ] Имена процедур — с префиксом алиаса расширения
- [ ] Нет прямых правок оригинального кода в заимствованных модулях
- [ ] Не удаляются существующие элементы заимствованных объектов
- [ ] Указано назначение расширения (Patch/Customization/AddOn)
- [ ] Префикс расширения не содержит буквы `ё`
- [ ] Изменённые свойства заимствованных реквизитов зафиксированы в `PropertyState` и прокомментированы
