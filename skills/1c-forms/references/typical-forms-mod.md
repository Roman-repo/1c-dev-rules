# Практика: Программная доработка типовых форм

> Правила программной модификации **типовых** форм БСП: добавление элементов кодом, размещение, проверка заполнения, команды формы.
> Адаптировано из [`dev-standards-forms.md`](https://github.com/comol/ai_rules_1c/blob/main/content/rules/dev-standards-forms.md) репозитория `ai_rules_1c`.
>
> **Для создания НОВЫХ форм** (своих объектов с префиксом `<ПрефиксПроекта>`) — см. [typical-forms-new.md](./typical-forms-new.md):
> там про 5 обязательных областей модуля формы, проверку заполнения и `modifiesStoredData`.

## Когда применять

При доработке типовых форм конфигурации (БСП, отраслевые решения) — когда нужно добавить реквизиты/элементы, не трогая визуальный редактор формы. Это канон для работы с типовыми конфигурациями.

---

## Программная модификация типовых форм

🔴 Все модификации типовых форм выполняются **программно**, не визуально. Элементы создаются в обработчике `ПриСозданииНаСервере` (или через подписку / расширение).

Почему программно: при обновлении типовой конфигурации визуальная форма перетирается, и ваши изменения пропадут. Программное создание переживает обновление.

---

## Размещение добавленных элементов

- Если в форме есть **страницы (вкладки)** — добавляйте элементы на **отдельную вкладку** (например, «Дополнительно» или с названием с `{PREFIX}`).
- Если вкладок нет — создайте **группу без заголовка** для добавленных элементов.
- Имена добавленных элементов типовой формы — с префиксом `{PREFIX}` (в проект — ``).

---

## Новые формы (нетиповые объекты)

При создании форм для своих объектов:

- Разделяйте шапку и табличные части на **отдельные страницы**: «Основное» (шапка), затем по странице на каждую табличную часть.
- Заполняйте свойство **«Путь к данным заголовка»** для страниц с табличными частями.
- Поля ссылочного типа — максимальная ширина **27 символов**.
- Многострочные поля комментариев — ширина **79**, высота **3**.

---

## Проверка заполнения

- Используйте свойство **«Проверка заполнения»** у реквизитов формы.
- Перед записью / проведением вызывайте `ПроверитьЗаполнение()`:

```bsl
Если Не ПроверитьЗаполнение() Тогда
    Возврат;
КонецЕсли;
```

📖 Стандарт: [№463](https://github.com/zeegin/v8std/blob/main/docs/std/463.md) ОбработкаПроверкиЗаполнения · [№478](https://github.com/zeegin/v8std/blob/main/docs/std/478.md) Подсказка и проверка заполнения

---

## Команды формы

- При создании команд, модифицирующих данные — включайте флаг **«Изменяет сохраняемые данные»**. Это важно для блокировок и корректного поведения платформы.

---

## Шаблон: программное добавление элемента в `ПриСозданииНаСервере`

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)

    // Добавляем реквизит формы
    Реквизиты = Новый Массив;
    Реквизиты.Добавить(Новый РеквизитФормы("ДополнительнаяИнформация",
        Новый ОписаниеТипов(Булево)));
    ИзменитьРеквизиты(Реквизиты);

    // Добавляем элемент на отдельную страницу
    Элемент = Элементы.Добавить("ДополнительнаяИнформация",
        Тип("ПолеФормы"), Элементы.ГруппаДополнительно);
    Элемент.Вид = ВидПоляФормы.ПолеФлажка;
    Элемент.ПутьКДанным = "ДополнительнаяИнформация";
    Элемент.Заголовок = "Дополнительная информация";

КонецПроцедуры
```

---

## Чек-лист ревью модификации типовой формы

- [ ] Модификация выполняется программно в `ПриСозданииНаСервере` (не визуально)
- [ ] Добавленные элементы — с префиксом проекта (``)
- [ ] Элементы сгруппированы на отдельной вкладке или в группе
- [ ] Проверка заполнения через свойство и `ПроверитьЗаполнение()`
- [ ] Команды, модифицирующие данные, помечены «Изменяет сохраняемые данные»
- [ ] При обновлении типовой конфигурации модификация не потеряется

## Связанные карточки

- Скил `1c-forms` — события формы, минимизация клиентского кода
- Скил `1c-extensions` — перехватчики для типовых модулей
- Скил `1c-metadata` → `module-templates` — структура модуля формы
- Скил `1c-metadata` → `metadata-xml` — если правите XML формы вручную
