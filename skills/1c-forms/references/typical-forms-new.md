# Практика: Создание новых форм

> Правила создания **новых** (нетиповых) форм для своих объектов конфигурации.
> Создана при разделении `typical-forms-mod.md`: та карточка — для модификации типовых форм БСП,
> эта — для создания форм с нуля (новые обработки, справочники, документы проекта).

## Когда применять

При создании новой формы для объекта с префиксом `<ПрефиксПроекта>` — когда нет риска перезатирания
при обновлении БСП, но нужно соблюсти структуру, проверку заполнения и командный интерфейс.

---

## 1. Структура модуля формы — 5 обязательных областей

🔴 По стандарту [№630](https://github.com/zeegin/v8std/blob/main/docs/std/630.md) модуль формы содержит **5 областей**, даже пустые:

```bsl
#Область ОбработчикиСобытийФормы
#КонецОбласти

#Область ОбработчикиСобытийЭлементовШапкиФормы
#КонецОбласти

#Область ОбработчикиСобытийЭлементовТаблицыФормы<ИмяТаблицы>
#КонецОбласти

#Область ОбработчикиКомандФормы
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
#КонецОбласти
```

- Для **каждой** табличной части формы — своя область `ОбработчикиСобытийЭлементовТаблицыФормы<ИмяТаблицы>`.
- Пустую область оставляют пустой — не удалять, не пропускать.

📖 Подробнее: [module-templates.md](./module-templates.md)

---

## 2. Разделение шапки и табличных частей

- Разделяйте шапку и табличные части на **отдельные страницы**: «Основное» (шапка), затем по странице на каждую табличную часть.
- Заполняйте свойство **«Путь к данным заголовка»** для страниц с табличными частями.
- Поля ссылочного типа — максимальная ширина **27 символов**.
- Многострочные поля комментариев — ширина **79**, высота **3**.

---

## 3. Проверка заполнения — канонический путь

🔴 Не пишите валидацию вручную, если есть стандартный механизм. Два способа:

**Способ 1 — свойство реквизита «Проверка заполнения»** (в `.form` или через конструктор):
реквизит с проверкой `Авто`/`Выдавать ошибку` проверяется платформой автоматически.

**Способ 2 — `ПроверитьЗаполнение()` в обработчике:**

```bsl
&НаКлиенте
Процедура Загрузить(Команда)

    Если НЕ ПроверитьЗаполнение() Тогда
        Возврат;
    КонецЕсли;

    // ... дальнейшая логика
КонецПроцедуры
```

📖 Стандарты: [№463](https://github.com/zeegin/v8std/blob/main/docs/std/463.md) ОбработкаПроверкиЗаполнения · [№478](https://github.com/zeegin/v8std/blob/main/docs/std/478.md) Подсказка и проверка заполнения

> **Когда своя валидация оправдана:** массовая загрузка из внешнего источника (Excel, файл),
> где ошибки нужно собирать построчно в таблицу результатов, а не обрывать на первой ошибке.
> В этом случае — комментируйте «почему не ПроверитьЗаполнение».

---

## 4. Команды, модифицирующие данные

🔴 Команды формы, которые записывают/изменяют объекты — должны иметь флаг **«Изменяет сохраняемые данные»**.
В XML формы это `<modifiesStoredData>true</modifiesStoredData>` внутри блока `formCommands`
(после `</action>`, до `<currentRowUse>`):

```xml
<formCommands>
  <name>Загрузить</name>
  ...
  <action xsi:type="form:FormCommandHandlerContainer">
    <handler><name>Загрузить</name></handler>
  </action>
  <modifiesStoredData>true</modifiesStoredData>
  <currentRowUse>DontUse</currentRowUse>
</formCommands>
```

Почему важно: платформа использует этот признак для корректного поведения блокировок и
объектного кэша. Команда без флага, модифицирующая данные, может работать некорректно.

---

## 5. Бизнес-логика — вне модуля формы

По стандарту [№629](https://github.com/zeegin/v8std/blob/main/docs/std/629.md) клиентские процедуры —
только UI и вызовы сервера. Серверная бизнес-логика (запросы, расчёты, запись):

- **Общий модуль** `<Подобласть>Сервер` — для переиспользуемых операций.
- **Модуль объекта** — для логики, привязанной к конкретному объекту.

> **Допустимое исключение:** форма обработки-утилиты (разовая загрузка, импорт), где логика
> не переиспользуется и не дублирует существующие операции. В этом случае — серверные
> процедуры в модуле формы приемлемы, но решение должно быть осознанным.

📖 [arch-checklist.md §1](../arch-checklist.md) · [forms.md №629, №630](../forms.md)

## Чек-лист ревью новой формы

- [ ] В модуле формы все 5 обязательных областей (даже пустые) — №630
- [ ] Каждая табличная часть имеет свою область обработчиков
- [ ] Проверка заполнения через свойство или `ПроверитьЗаполнение()`, либо обоснована своя валидация
- [ ] Команды, модифицирующие данные, помечены `modifiesStoredData`
- [ ] Бизнес-логика вынесена в общий модуль/модуль объекта (или осознанно оставлена в форме)
- [ ] Реквизиты с проверкой заполнения — для обязательных полей
