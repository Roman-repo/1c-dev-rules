> Полный список раздела — в [`std/forms.md`](../../../std/forms.md) и [`ui.md`](../../../std/ui.md).

## №459 — Значения, влияющие на поведение клиентского приложения

**Критичность:** 🔴 Блокирующее

**Суть:** Значения, от которых зависит видимость/доступность элементов формы (функциональные опции, параметры сеанса), нужно читать **на сервере в `ПриСозданииНаСервере`** и кэшировать в реквизитах формы. Не запрашивать их повторно в каждом обработчике.

✅ **Как в проект (правильно):**
```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
    // читаем ФО один раз, используем во всех обработчиках
    ФОИспользоватьЗаказы = ПолучитьФункциональнуюОпцию("ИспользоватьЗаказы");
    ФОИспользоватьСкладскойУчет = ПолучитьФункциональнуюОпцию("ИспользоватьСкладскойУчет");
КонецПроцедуры;
```

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/459.md)
См. также: №491

## №629 — Минимизация кода на клиенте

**Критичность:** 🔴 Блокирующее

**Суть:** В клиентских процедурах (`&НаКлиенте`) — только обработка UI-событий и вызовы серверных функций. Вся бизнес-логика и работа с данными — на сервере. Клиентский код не должен содержать запросов, расчётов, сложных условий.

❌ **Неправильно:**
```bsl
&НаКлиенте
Процедура ДоговорПриИзменении(Элемент)
    Если Договор.Контрагент <> Контрагент Тогда           // обращение к данным на клиенте
        ПоказатьПредупреждение(, "Контрагент не совпадает");
        Возврат;
    КонецЕсли;
    Сумма = Сумма * Договор.Коэффициент;                  // расчёт на клиенте
КонецПроцедуры;
```

✅ **Правильно:**
```bsl
&НаКлиенте
Процедура ДоговорПриИзменении(Элемент)
    Если НЕ ПроверитьДоговорНаСервере() Тогда
        ПоказатьПредупреждение(, "Контрагент не совпадает");
        Возврат;
    КонецЕсли;
КонецПроцедуры;
```

🔍 Авто-проверка: `#bslls:CommonModuleMissingAPIClient`, косвенно
📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/629.md)

## №400 — Информирование пользователя

**Критичность:** 🟡 Важно

**Суть:** Не используйте `Сообщить` для ошибок валидации. Применяйте `ОбщегоНазначенияКлиентСервер.СообщитьПользователю(...)` с привязкой к полю — сообщение появится у нужного элемента формы.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/400.md)

## №399 — Запрет редактирования полей таблицы по условию

**Критичность:** 🟡 Важно

**Суть:** Доступность/видимость реквизитов формы настраивайте **условным оформлением** (`УстановитьУсловноеОформление`), а не программно в обработчиках `ПриИзменении`/`ПриАктивизацииСтроки`. Условное оформление декларативно и быстрее.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/399.md)
См. также: №457

## №404 — Открытие форм

**Критичность:** 🔴 Блокирующее

**Суть:** Формы открывайте через `ОткрытьФорму(...)` / `ОткрытьФормуМодально(...)` (последнее — только где допустимо) с параметрами. Не через `ПолучитьФорму().Открыть()` — это устаревший синхронный путь. Параметры передавайте через структуру.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/404.md)
См. также: №741, №742

## №409 — `РеквизитФормыВЗначение` и `ДанныеФормыВЗначение`

**Критичность:** 🟡 Важно

**Суть:** Эти методы — превращают данные формы в объект/значение на сервере. Использовать осторожно: они дорогие (сериализация всего объекта). Чаще можно обойтись чтением конкретных реквизитов через `НайтиОбъект...` или параметры.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/409.md)

## №411 — Параметры выбора и связи параметров выбора

**Критичность:** 🟡 Важно

**Суть:** Отборы при выборе значения (например, «только подчинённые контрагенты») задавайте через **связи параметров выбора** в метаданных или программно через `УстановитьПараметрыВыбора`, а не через `Оповещение` или глобальные переменные.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/411.md)

---

## №507 — Флаги «Автовыбор» и «Автоотметка» незаполненного

**Критичность:** 🟡 Важно

**Суть:** Флаги `АвтовыборНезаполненного` / `АвтоотметкаНезаполненного` включать осознанно — они вызывают неявные серверные вызовы при выборе. Не включать «на всякий случай».

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/507.md)

## №536 / №545 — Обращение из кода к элементам формы

**Критичность:** 🟡 Важно

**Суть:**
- **№536** — к автоматически создаваемым элементам формы (сгенерированным из реквизитов) обращайтесь через `Элементы.ИмяРеквизита`. Не плодите программно созданные элементы, если можно использовать автоматические.
- **№545** — к пользовательским (добавленным вручную) элементам — по их имени. Чётко различайте, к каким обращаетесь.

📖 №536 [авто-элементы](https://github.com/zeegin/v8std/blob/main/docs/std/536.md) · №545 [польз. элементы](https://github.com/zeegin/v8std/blob/main/docs/std/545.md)

## №557 — Работа с пользовательскими настройками

**Критичность:** 🟡 Важно

**Суть:** Пользовательские настройки формы (отборы, колонки) — через механизм БСП `КлючПользовательскихНастроек` / `ХранилищеВариантовОтчетов`. Не самописное сохранение в файл или регистр сведений.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/557.md)

## №589 — Блокирующая или независимая форма

**Критичность:** 🟡 Важно

**Суть:** При открытии формы выбирайте: блокирующее (`ОткрытьФормуМодально` / `ОткрытьФорму` с режимом блокировки владельца) — когда нужно прервать поток; независимое (`ОткрытьФорму`) — когда пользователь может работать дальше. Не использовать модальное без необходимости.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/589.md)
См. также: №742, №703

## №628 — Использование `ДанныеФормыКоллекция`

**Критичность:** 🟡 Важно

**Суть:** Для работы с табличными частями и таблицами формы в коде используйте `ДанныеФормыКоллекция` и методы `Скопировать(...)`, не выгрузку в `ТаблицаЗначений` и обратно без необходимости.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/628.md)

## №630 — Правила создания модулей форм

**Критичность:** 🟡 Важно

**Суть:** В модуле формы — только обработчики событий и процедуры-обёртки. Бизнес-логика — в общих модулях (серверных). Структура модуля формы — по областям (см. скил `1c-metadata` → `module-templates`).

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/630.md)
См. также: №629

## №702 — Реквизит `Ссылка` и «Использовать всегда» в динамических списках

**Критичность:** 🔴 Блокирующее

**Суть:** В динамическом списке объектов всегда выводите поле `Ссылка` и установите признак «Использовать всегда». Без него платформа не сможет корректно открывать и обновлять строки, а в условном оформлении — ссылаться на объект.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/702.md)
См. также: №732, №710

## №710 — Условное оформление в формах

**Критичность:** 🟡 Важно

**Суть:** Условное оформление (`УстановитьУсловноеОформление`) — для подсветки, доступности, видимости полей на основе значений. Эффективнее программных изменений в обработчиках, поддерживается платформой.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/710.md)
См. также: №399

## №741 — Открытие параметризованных форм

**Критичность:** 🟡 Важно

**Суть:** При открытии формы с отбором/параметром передавайте параметры через `ПараметрыФормы` (структуру) — стандартный набор ключей БСП (`Отбор`, `ТекущаяСтрока`, `ЗначениеКлюча` и т.д.). Не через глобальные переменные.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/741.md)
См. также: №404

## №742 — Блокирующее/независимое открытие форм объектов

**Критичность:** 🟡 Важно

**Суть:** Форму объекта из списка открывайте в режиме, согласованном с UX: обычно независимое (пользователь работает с несколькими окнами). Модальное — только для критичных диалогов. Не блокируйте список формами объектов.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/742.md)
См. также: №589

- [ ] Клиентские процедуры содержат только UI-логику (№629)
- [ ] Доступность полей — через условное оформление, не программно (№399)
- [ ] Сообщения об ошибках — с привязкой к полю (№400)
- [ ] Серверные вызовы минимальны и сгруппированы (№487)
- [ ] Тяжёлые операции — асинхронно (№642/№755)

## Справочное приложение: события и свойства по типам форм

> Справочные таблицы, извлечённые из спецификации `1c-form-spec.md` репозитория
> [cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills). Помогают выбрать правильные
> обработчики и свойства при создании формы. Форматонезависимо — это про платформу 1С,
> применимо к EDT и Конфигуратору.

### События формы — полный список

| Имя события | Контекст | Описание |
|---|---|---|
| `OnCreateAtServer` | Сервер | Создание формы на сервере (инициализация) |
| `OnOpen` | Клиент | Открытие формы на клиенте |
| `BeforeClose` | Клиент | Перед закрытием формы |
| `OnClose` | Клиент | При закрытии формы |
| `BeforeWrite` | Клиент | Перед записью объекта |
| `BeforeWriteAtServer` | Сервер | Перед записью на сервере |
| `OnWriteAtServer` | Сервер | При записи на сервере |
| `AfterWriteAtServer` | Сервер | После записи на сервере |
| `AfterWrite` | Клиент | После записи объекта |
| `OnReadAtServer` | Сервер | При чтении объекта |
| `NotificationProcessing` | Клиент | Обработка межформенных оповещений |
| `ChoiceProcessing` | Клиент | Обработка результата выбора |
| `NewWriteProcessing` | Сервер | Создание нового объекта |
| `FillCheckProcessingAtServer` | Сервер | Проверка заполнения |
| `OnLoadDataFromSettingsAtServer` | Сервер | Загрузка настроек (списки) |
| `OnLoadUserSettingsAtServer` | Сервер | Загрузка пользовательских настроек (отчёты) |
| `OnSaveUserSettingsAtServer` | Сервер | Сохранение пользовательских настроек (отчёты) |
| `URLProcessing` | Клиент | Обработка навигационных ссылок |

### Типичные комбинации событий по типам форм

| Тип формы | События |
|---|---|
| **Диалог** | `OnCreateAtServer` + `OnOpen` |
| **Документ** | `OnCreateAtServer` + `OnOpen` + `BeforeWriteAtServer` + `OnWriteAtServer` + `AfterWrite` |
| **Справочник** | `OnCreateAtServer` + `OnOpen` + `OnReadAtServer` + `BeforeWriteAtServer` + `AfterWrite` + `NotificationProcessing` |
| **Отчёт** | `OnCreateAtServer` + `OnOpen` + `BeforeClose` + `OnClose` + `OnLoadUserSettingsAtServer` + `OnSaveUserSettingsAtServer` + `NotificationProcessing` + `ChoiceProcessing` + `URLProcessing` |
| **Обработка** | `OnCreateAtServer` + `OnOpen` + `NotificationProcessing` |
| **Список** | `OnCreateAtServer` + `OnOpen` + `NotificationProcessing` + `OnLoadDataFromSettingsAtServer` |

> 💡 В EDT имена событий — русские (`ПриСозданииНаСервере`, `ПриОткрытии`...). В таблице даны
> английские имена из спецификации — это канон, который платформа использует внутри.
