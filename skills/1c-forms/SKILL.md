# 1c-forms — формы, архетипы, типовые

> Управляемые формы 1С. Главное правило: форма — UI и вызовы сервера, бизнес-логика и данные — на сервере.

## 🔴 №629 — Бизнес-логика вне формы

Форма — только UI (видимость, доступность, вызовы сервера). Бизнес-логика (расчёты, проверки, обращения к данным ИБ) — в общих модулях на сервере.

| В форме | На сервере |
|---|---|
| UI-логика (видимость, доступность элементов) | Бизнес-логика (расчёт, проведение, проверки) |
| Вызовы сервера (`&НаСервере`, `&НаСервереБезКонтекста`) | Обращение к данным ИБ |
| Условное оформление (а не кодом) | Переиспользуемые операции |

## 🔴 5 обязательных областей модуля формы

```bsl
#Область ОбработчикиСобытийФормы
#КонецОбласти

#Область ОбработчикиСобытийЭлементовШапкиФормы
#КонецОбласти

#Область ОбработчикиСобытийЭлементовТаблицыФормы<ИмяТаблицы>
#КонецОбласти

#Область ОбработчикиКомандФормы
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
#КонецОбласти
```

Все 5 — **даже пустые**. Для каждой **таблицы** формы — своя область `ОбработчикиСобытийЭлементовТаблицыФормы<Имя>`; таблица динамического списка — тоже таблица: у формы списка это `ОбработчикиСобытийЭлементовТаблицыФормыСписок` (канон подтверждён типовыми формами списков).

⚠️ **Если у формы нет табличных частей** — область `ОбработчикиСобытийЭлементовТаблицыФормы<Имя>` **опускается** (остаётся 4 канонические: `ОбработчикиСобытийФормы` → `ОбработчикиСобытийЭлементовШапкиФормы` → `ОбработчикиКомандФормы` → `СлужебныеПроцедурыИФункции`). Создавать «пустую» область таблицы без суффикса `<Имя>` **нельзя** — она должна соответствовать реальной ТЧ. Суффикс `<Имя>` — обязательная часть имени области, без него область не создаётся.

## 🔴 №459 — ФО и параметры сеанса читаются один раз

`ПолучитьФункциональнуюОпцию(...)` — в `ПриСозданииНаСервере`, кэшировать в реквизит/переменную. Не вызывать повторно в других обработчиках.

---

## №399 / №400 — Условное оформление и сообщения

- **Доступность/видимость полей** — через **условное оформление**, не `Элементы.X.Доступность = Ложь` кодом в `ПриИзменении`.
- **Сообщения пользователю** — `ОбщегоНазначенияКлиентСервер.СообщитьПользователю` (функция БСП, не платформенная — см. 1c-ui-ux) с привязкой к полю, не `Сообщить`.

---

## 🔴 №489 — Динамические списки «плоские»

Самый «горячий» запрос формы — перевыполняется при каждом обновлении, у каждого пользователя:
- **Никаких** соединений с ВТ и подзапросами (№655/№732).
- **Никаких** обращений через точку к реквизитам ссылок (`.Ссылка.Организация` — неявное соединение).
- Минимум соединений вообще.
- `АвтоОбновление = Истина` — только если нужно; период не короткий; для невидимых списков — `Ложь`.

---

## 🔴 №703 — Запрет модальных окон и синхронных вызовов

В управляемых формах — **никаких** `ОткрытьФормуМодально` / `Предупреждение` / `Вопрос`. Только асинхронные: `ПоказатьПредупреждение`, `ПоказатьВопрос`, `ОписаниеОповещения`.

Это требование веб-клиента.

⚠️ `Асинх Процедура` для обработчиков событий формы (`ПриОткрытии`, `ПередЗакрытием`) — **нельзя**: `Отказ` игнорируется. Подробности — скил `1c-async`.

---

## 🔴 `modifiesStoredData` для команд, модифицирующих данные

Команда формы, которая вызывает серверную процедуру, **записывающую данные** (проведение, запись объекта, массовое изменение), должна иметь флаг `ИзменяетСохраняемыеДанные` (`modifiesStoredData=true`). Это влияет на блокировки и предупреждения.

---

## №636 — Контекстный vs внеконтекстный сервер

`&НаСервере` (контекстный) — когда форме нужны данные формы. `&НаСервереБезКонтекста` — когда данные формы не нужны (расчёт по параметрам). Каждый round-trip с контекстом дороже — сокращайте.

---

## Архетипы форм

Формы делятся на архетипы по типу объекта:
- **Форма документа** — шапка + ТЧ + движения.
- **Форма списка** — динамический список + отборы.
- **Форма справочника** — шапка + (опц.) ТЧ.
- **Форма обработки/отчёта** — реквизиты + команда «Выполнить».

Компоновка, именование элементов, конвенции — `references/form-archetypes.md`.

## Мини-чек-лист по формам

- [ ] Бизнес-логика вынесена на сервер (№629)
- [ ] Области формы: 5 (с ТЧ) или 4 (без ТЧ) — присутствуют даже пустые
- [ ] ФО/параметры сеанса — один раз в `ПриСозданииНаСервере` (№459)
- [ ] Доступность полей — через условное оформление, не кодом (№399)
- [ ] Сообщения — `СообщитьПользователю` с привязкой (№400)
- [ ] Динамический список «плоский», без ВТ и точек (№489/№732)
- [ ] Нет модальных окон и синхронных вызовов (№703)
- [ ] Команды, модифицирующие данные — `modifiesStoredData=true`
- [ ] Внеконтекстный сервер где форма не нужна (№636)
- [ ] Тяжёлые операции — асинхронно с индикатором (№642)
