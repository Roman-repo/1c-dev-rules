# Практика: Блокировки и транзакции

> Канонические правила блокировок и транзакций в 1С: управляемый режим, границы транзакций, порядок блокировок, предотвращение дедлоков, диагностика через техжурнал.
> Адаптировано из [`locks-and-transactions.md`](https://github.com/comol/ai_rules_1c/blob/main/content/rules/locks-and-transactions.md) репозитория `ai_rules_1c`.

## Когда применять

При проектировании проведения / многодокументных операций, отладке конфликтов блокировок, расширении существующего транзакционного пути.

---

## 1. Режим управления блокировкой конфигурации

Свойство конфигурации **«Режим управления блокировкой данных»** = `Управляемый` (Managed) для всей конфигурации.

- Смешанный режим скрывает баги — код, написанный под автоматическими блокировками, внезапно конфликтует под управляемым режимом.
- Управляемый режим — единственный, где гранулярность блокировок под контролем разработчика (по таблице/ключу, а не по строке-странице).
- Современная БСП предполагает управляемый режим.

## 2. Границы транзакций

### Неявные транзакции

Платформа открывает свою транзакцию вокруг:
- `Записать()` / `Записать(РежимЗаписиДокумента....)` — оборачивает **`ПередЗаписью` → запись → `ПриЗаписи` → проведение (`ОбработкаПроведения`)**.
- `Удалить()` ссылочного объекта.
- `НаборЗаписей.Записать()` для наборов записей регистров.
- Материализация движений в конце `ОбработкаПроведения`.

🔴 **Внутри `ПередЗаписью` / `ПриЗаписи` / `ОбработкаПроведения` НЕ открывайте свои `НачалоТранзакции` / `ЗафиксироватьТранзакцию`.** Транзакция уже открыта; вложенный вызов фальшивит savepoint, но отключает корректный rollback внешней ошибки.

### Явные транзакции в вызывающем коде

Когда вызывающему коду нужно атомарно записать несколько объектов или совместить запись с правкой регистров — открывайте транзакцию там:

```bsl
НачалоТранзакции();

Попытка
    Документ.Записать(РежимЗаписиДокумента.Проведение);
    // ... дополнительные изменения ...
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();

    ДанныеОшибки = Новый Структура;
    ДанныеОшибки.Вставить("Документ", Документ.Ссылка);
    ДанныеОшибки.Вставить("Подробно", ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));

    ЗаписьЖурналаРегистрации(
        "Проведение." + Документ.Метаданные().Имя + ".Ошибка",
        УровеньЖурналаРегистрации.Ошибка,
        Документ.Метаданные(),
        Документ.Ссылка,
        НСтр("ru = 'Не удалось провести документ.'"),
        ДанныеОшибки);

    ВызватьИсключение;
КонецПопытки;
```

Правила:
- Шаблон `НачалоТранзакции()` → `Попытка` … `ЗафиксироватьТранзакции()` → `Исключение` `ОтменитьТранзакцию()` `ВызватьИсключение` `КонецПопытки` — **единственный** правильный. Любое отклонение (без `Попытка`, без `ОтменитьТранзакцию`, без re-raise) — дефект.
- **Диагностировать, не глотать.** Логировать ошибку и `ВызватьИсключение`.
- **Перепроверить `ТранзакцияАктивна()`** перед вторым `ОтменитьТранзакцию` — только в диагностических целях.

### 🔴 Запрещено внутри транзакций

- **Пользовательские диалоги** (`ВопросАсинх`, `ПоказатьЗначение`, выбор файла). Любое ожидание пользовательского ввода держит блокировки и застолбляет другие сеансы.
- **Длительные операции** (`ДлительныеОперации`, сетевые вызовы, внешние компоненты). Выносите за пределы транзакции.
- **`ЗаписьЖурналаРегистрации` с `Сообщить`** в клиентском контексте — сообщение уходит в UI, заблокированный за транзакцией.

📖 Стандарт: [№783](https://github.com/zeegin/v8std/blob/main/docs/std/783.md) Транзакции

## 3. Примитивы управляемых блокировок

```bsl
Блокировка = Новый БлокировкаДанных;

ЭлементБлокировки = Блокировка.Добавить("РегистрНакопления.ТоварыНаСкладах");
ЭлементБлокировки.Режим = РежимБлокировкиДанных.Исключительный;
ЭлементБлокировки.ИсточникДанных = Товары;
ЭлементБлокировки.ИспользоватьИзИсточникаДанных("Номенклатура", "Номенклатура");
ЭлементБлокировки.ИспользоватьИзИсточникаДанных("Склад",       "Склад");

Блокировка.Заблокировать();
```

Правила:
- **Блокировать перед чтением**, затем читать, затем писать. Чтение без блокировки с последующей записью создаёт незащищённое окно для конкурентного проведения.
- **Блокировать регистр**, не документ. Блокировка документа не защищает регистр; следующее проведение может прочитать устаревшие остатки.
- **`ИсточникДанных`**, не ручная итерация. Передавайте табличную часть документа (или `ТаблицаЗначений`) как `ИсточникДанных` и используйте `ИспользоватьИзИсточникаДанных` для маппинга колонок; платформа компилирует один эффективный запрос блокировки.
- **Блокировка живёт до конца текущей транзакции.** Раньше освободить нельзя; можно только завершить транзакцию.

### Режимы

| `РежимБлокировкиДанных` | Для чего |
|---|---|
| `Исключительный` | Путя чтение-модификация-запись: проведение, массовая запись, перерасчёты. Блокирует и читателей, и писателей. |
| `Разделяемый` | Путя чтения, которые должны оставаться консистентными в одной транзакции (отчёт, читающий несколько регистров под одним snapshot). Разделяемые блокировки совместимы; исключительная против разделяемой — ждёт. |

По умолчанию: `Исключительный` для любого пути записи. `Разделяемый` — осознанно.

📖 Стандарт: [№460](https://github.com/zeegin/v8std/blob/main/docs/std/460.md) Управляемый режим блокировки

## 4. Порядок блокировок — контракт от дедлоков

Для дедлока нужны две транзакции, берущие блокировки в разном порядке. Фикс — **зафиксировать порядок блокировок на уровне проекта**.

Установите канонический порядок блокируемых таблиц и документируйте его в `memory.md` как проектное правило. Пример:

```
1. РегистрНакопления.ТоварыНаСкладах
2. РегистрНакопления.ТоварыКПередаче
3. РегистрСведений.ЦеныНоменклатуры
4. РегистрНакопления.ВзаиморасчетыСКонтрагентами
```

Правила:
- Каждое проведение, затрагивающее больше одного регистра из списка, блокирует их в указанном порядке. Без исключений.
- Новые регистры добавлять в конец, не вставлять в середину (перенумерация ломает существующие ревью).
- Межудокументные операции (один документ проводит другой) наследуют тот же порядок.

Если наблюдаете дедлок под нагрузкой, вопрос никогда не «как ретраить» — а «какая транзакция взяла блокировки не в порядке». Чините порядок; ретраи — пластырь.

## 5. Паттерны блокировок

### Проведение документа, затрагивающего несколько регистров

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

    // 1. Строим объект блокировки один раз, в каноническом порядке.
    Блокировка = Новый БлокировкаДанных;

    БлокТовары = Блокировка.Добавить("РегистрНакопления.ТоварыНаСкладах");
    БлокТовары.Режим = РежимБлокировкиДанных.Исключительный;
    БлокТовары.ИсточникДанных = Товары;
    БлокТовары.ИспользоватьИзИсточникаДанных("Номенклатура", "Номенклатура");
    БлокТовары.ИспользоватьИзИсточникаДанных("Склад",       "Склад");

    БлокВзаиморасчеты = Блокировка.Добавить("РегистрНакопления.ВзаиморасчетыСКонтрагентами");
    БлокВзаиморасчеты.Режим = РежимБлокировкиДанных.Исключительный;
    БлокВзаиморасчеты.УстановитьЗначение("Контрагент", Контрагент);

    Блокировка.Заблокировать();

    // 2. Читаем остатки и валидируем.
    // 3. Пишем движения через Движения.X.Добавить / Записать = Истина.

КонецПроцедуры
```

### Обновление статуса вне проведения

Для регистров сведений как лога статусов (`СтатусыЗаказов`, `СтатусыИнтеграции`) — запись набора с `НаборЗаписей.Заблокировать()` в явной транзакции:

```bsl
НачалоТранзакции();

Попытка

    НаборЗаписей = РегистрыСведений.СтатусыИнтеграции.СоздатьНаборЗаписей();
    НаборЗаписей.Отбор.Заказ.Установить(СсылкаЗаказа);
    НаборЗаписей.Заблокировать();
    НаборЗаписей.Прочитать();

    // ... мутируем набор ...

    НаборЗаписей.Записать();
    ЗафиксироватьТранзакцию();

Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;
КонецПопытки;
```

`НаборЗаписей.Заблокировать()` — удобная форма управляемой блокировки в рамках фильтра набора.

## 6. Диагностика конфликтов и дедлоков

### Симптомы

- **«Конфликт блокировок при выполнении транзакции»** — спорадический таймаут на регистре; причина: другая транзакция держит тот же ключ в несовместимом режиме дольше `MaxLockWait` (по умолчанию 20 с).
- **«Deadlock»** — две транзакции ждут друг друга; причина: нарушен порядок блокировок (§4).
- **«Запись регистра не удалось получить»** при проведении — обычно конфликт блокировки на самом регистре, а не на наборе записей.

### Инструменты диагностики

- **Технологический журнал (`logcfg.xml`)** — включите события `TLOCK` и `TDEADLOCK` для проблемного регистра. Журнал фиксирует, кто держит что и кто ждёт. Это единственный авторитетный источник «какие две транзакции дедлочатся».
- **`ТранзакцияАктивна()`** — проверяет, жива ли текущая транзакция; полезно только для self-consistency checks, не для кросс-сессионной диагностики.
- **DMVs MS SQL** (для серверной ИБ) — `sys.dm_tran_locks`, `sys.dm_os_waiting_tasks` для живых снимков, когда техжурнала недостаточно.
- **Replay проведения** — перепроведите падающий документ под отладчиком для точной последовательности блокировок.

## Чек-лист ревью блокировок/транзакций

- [ ] Режим блокировки конфигурации — Управляемый
- [ ] Внутри `ОбработкаПроведения` нет своих `НачалоТранзакции`
- [ ] Шаблон явной транзакции — `Начать` → `Попытка` → `Зафиксировать` → `Исключение` → `Отменить` + `ВызватьИсключение`
- [ ] Блокировка берётся **до** чтения, на уровне регистра
- [ ] Используется `ИсточникДанных`, не ручная итерация
- [ ] Порядок блокировок соответствует проектному канону
- [ ] Внутри транзакции нет диалогов и длительных операций
