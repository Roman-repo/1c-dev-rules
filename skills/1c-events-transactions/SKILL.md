# 1c-events-transactions — проведение, блокировки, транзакции, язык

> Обработчики событий объектов/форм, проведение документов, шаблоны транзакций, управляемые блокировки. Это «горячая» зона — ошибки здесь дорого стоят (deadlock'и, рассинхрон данных).

## 🔴 №783 — Транзакции: короткие, только запись

Транзакция должна быть **короткой** и охватывать только запись.

Шаблон (как в БСП):
```bsl
// Чтение и подготовка данных — ДО транзакции
ДанныеДляЗаписи = ПодготовитьДанные();   // запросы, .ПолучитьОбъект(), вычисления

НачатьТранзакцию();
Попытка
    // ... только запись ...
    ЗаписатьДанные(ДанныеДляЗаписи);
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;   // обязательно!
КонецПопытки;
```

❌ **Неправильно** — чтение внутри транзакции:
```bsl
НачатьТранзакцию();
Попытка
    Выборка = Запрос.Выполнить().Выбрать();   // 🔴 чтение ВНУТРИ транзакции
    Пока Выборка.Следующий() Цикл ... КонецЦикла;
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;
КонецПопытки;
```

⚠️ **Исключение:** чтение внутри транзакции допустимо для read-modify-write с **явной `БлокировкаДанных`** — когда без блокировки нельзя гарантировать консистентность остатка. Это осознанный компромисс с комментарием-обоснованием (см. `references/locks-transactions.md` §3).

## 🔴 №460 — Управляемый режим блокировки

В прикладном коде — управляемые блокировки (`БлокировкаДанных`), не исключительные. Исключительные — только в особых случаях, с обоснованием в комментарии.

---

## №648 — Точечное чтение данных

Не читать «на всякий случай» весь объект. 2 поля — читайте 2 поля, а не `Объект.Ссылка` целиком.

❌ `ДокОбъект = ДокСсылка.ПолучитьОбъект();` — вытянули ВСЕ реквизиты
✅ `Значения = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(ДокСсылка, "Организация");`

---

## №450 / №464 / №465 — Обработчики проведения

| Событие | Когда | Что делать |
|---|---|---|
| `ОбработкаПроведения` | При проведении | Формировать движения; транзакция уже открыта платформой — **не вкладывать** `НачалоТранзакции` |
| `ОбработкаУдаленияПроведения` | При отмене проведения | Сформировать пустой набор / удалить движения |
| `ПередЗаписью` | Перед записью (проведён/непроведён) | Валидация, заполнение по умолчанию |

🔴 **Движения (`Движения.X`) — только в обработчиках проведения**, не из внешнего кода.

---

## №661 — Блокирующее чтение остатков

В начале транзакции проведения не делайте блокирующего чтения остатков без необходимости — это источник deadlock'ов. Только если действительно нужен read-modify-write с гарантией.

---

## Шаблон read-modify-write с блокировкой

```bsl
НачалоТранзакции();
Попытка
    // Блокировка ДО чтения: иначе два пользователя проведут одновременно
    // и получат отрицательный остаток.
    Блокировка = Новый БлокировкаДанных;
    ЭлементБлокировки = Блокировка.Добавить("РегистрНакопления.<Имя>");
    ЭлементБлокировки.УстановитьЗначение("Измерение", Значение);
    ЭлементБлокировки.Режим = РежимБлокировкиДанных.Исключительный;
    Блокировка.Заблокировать();

    // Чтение остатка (можно внутри транзакции — есть блокировка)
    Остаток = ПолучитьОстаток(Значение);

    // Проверка + запись
    Если Остаток < Расход Тогда
        ВызватьИсключение НСтр("ru = 'Недостаточно остатка'");
    КонецЕсли;

    // ... запись движения ...
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;
КонецПопытки;
```

## №499 / №790 — Исключения и логирование (кратко)

- `Попытка/Исключение` — **обязательно логировать** причину через `ЗаписьЖурналаРегистрации`. Молчаливый перехват — антипаттерн.
- `ВызватьИсключение` — с понятным локализованным текстом (`НСтр("ru = '…'")`), не технический мусор (`"err-1"`).

Полная карточка — скил `1c-logging`.

## Мини-чек-лист по проведению и транзакциям

- [ ] Транзакция короткая, только запись (№783)
- [ ] Чтение данных — **до** `НачалоТранзакции()`, не внутри (№783)
- [ ] `НачалоТранзакции()` **не** внутри `ОбработкаПроведения` (уже открыта платформой)
- [ ] `Попытка/Исключение` с `ОтменитьТранзакцию()` + `ВызватьИсключение`
- [ ] Блокировки управляемые (`БлокировкаДанных`), не исключительные (№460)
- [ ] Блокировка ДО чтения остатков при read-modify-write (№661)
- [ ] Движения — только в обработчиках проведения
- [ ] Чтение точечное (`ЗначенияРеквизитовОбъекта`, не `.ПолучитьОбъект()`) (№648)
- [ ] `Попытка/Исключение` логируется, не молчит (№499)
