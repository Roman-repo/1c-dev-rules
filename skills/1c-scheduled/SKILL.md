# 1c-scheduled — регламентные задания

> Регламентное задание (РЗ) должно быть идемпотентным и устойчивым — иначе «упав» один раз, оно может ломать данные или дублировать результаты.

## 🔴 №540 — Общие требования к РЗ

РЗ должно быть:
- **Идемпотентным** — повторный запуск не ломает данные и не дублирует результаты.
- **Устойчивым** — ошибки логируются и не «роняют» задание навсегда (шаблон `Попытка/Исключение` с `ЗаписьЖурналаРегистрации`).
- **Самодостаточным** — не требует интерактивного взаимодействия.

## 🔴 №539 — Запуск расписанием

РЗ запускаются **только** встроенным средством платформы (расписание), не внешними скриптами или ручным вызовом в коде.

## 🟡 №402 — Настройка расписания

Расписание РЗ по умолчанию — реалистичное. Не «каждую минуту», если хватает раза в час/день. Учитывать рабочие часы (для дневных операций) и ночь (для тяжёлых пересчётов).

## 🔴 №642 / №755 — Длительные операции

Тяжёлые расчёты (более 2–3 сек) — в фоновом задании из регламентного, не в интерактивном сеансе. На клиенте — асинхронно с индикатором.

## 🟡 №760 — Модель сервиса

Если конфигурация работает в модели сервиса (много арендаторов), РЗ должны учитывать разделение по областям данных.

## Шаблон устойчивого РЗ

```bsl
Процедура ОтправитьРассылку() Экспорт

    Попытка
        // ... основная логика ...
    Исключение
        // №499 — логируем причину, не роняем РЗ (№540 — устойчивость)
        ЗаписьЖурналаРегистрации(
            "<Префикс>ИмяРЗ.Ошибка",
            УровеньЖурналаРегистрации.Ошибка,
            , ,
            ОписаниеОшибки());
    КонецПопытки;

КонецПроцедуры
```

## Идемпотентность

Если РЗ пишет в очередь/регистр — перед записью новых данных **удалите** ранее созданные за тот же период, чтобы перезапуск не дублировал. Удаление — **вне транзакции** записи новых (№783).

## Чтение вне транзакции

Подготовка данных для РЗ (запросы, расчёты) — **до** `НачалоТранзакции()`. Внутри транзакции — только запись (№783).

## Права на целевые объекты

У пользователя, от имени которого стартует РЗ, должны быть права на все объекты, к которым РЗ обращается. Проверка: `grep -rl "Object.<Префикс>Имя" Roles/`.

---

## Мини-чек-лист по РЗ

- [ ] РЗ идемпотентное (повторный запуск не дублирует) (№540)
- [ ] РЗ устойчивое к ошибкам (`Попытка/Исключение` + лог) (№540)
- [ ] Запускается расписанием платформы, не внешними скриптами (№539)
- [ ] Расписание реалистичное, не «каждую минуту» (№402)
- [ ] Тяжёлые расчёты — в фоновых заданиях (№642)
- [ ] Права на целевые объекты у пользователя РЗ есть (№532)
- [ ] Чтение данных — вне транзакции записи (№783)
- [ ] В модели сервиса — с учётом разделения данных (№760)
