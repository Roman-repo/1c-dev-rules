# 1c-project-bootstrap — онбординг нового проекта

> Этот скил запускается **один раз** при подключении набора `1c-dev-rules` к новому проекту 1С. Он создаёт `AGENTS.md` с универсальными секциями (правила разработки) и заглушками под проектную специфику (которые заполняет пользователь).

## Когда применять

- Новый проект 1С, к которому подключается набор `1c-dev-rules`.
- Существующий проект без `AGENTS.md` или с неполным.
- Миграция с самописной системы правил на этот набор.

**Не применять** для повседневной разработки — после начальной настройки этот скил больше не нужен.

---

## Алгоритм работы

### Шаг 1. Собрать параметры проекта

Спросите у пользователя (или определите автоматически):

| Параметр | Как определить | Пример |
|---|---|---|
| **Имя проекта / тип конфигурации** | Спросить пользователя | «<прикладное решение> — <домен>» |
| **Префикс объектов** | Спросить; обычно виден по `ls` в `Catalogs/`, `Documents/` | `<префикс>_` (один или несколько) |
| **Путь к исходникам** | `find . -name "Configuration.mdo"` | `<проект>/src/` |
| **compatibilityMode** | `grep compatibilityMode Configuration.mdo` | `8.3.12` |
| **Базовые библиотеки** | Спросить / поискать общие модули БСП | БСП, БИП, … |
| **IDE** | Спросить | EDT, Конфигуратор |
| **Тесты / CI** | Спросить | Vanessa Automation, Jenkins |

### Шаг 2. Сгенерировать `AGENTS.md`

Из `templates/AGENTS.md.template` подставьте параметры и создайте `AGENTS.md` в корне проекта. Шаблон содержит:
- **Универсальные секции** (перенесены из references/agents-sections.md) — правила разработки, этапы работы, принципы.
- **Заглушки проектных секций** — помечены `<!-- PROJECT: ... -->`, пользователь заполняет их позже.

### Шаг 3. Создать `.zcode/config.json` (если ещё нет)

Если в проекте нет `.zcode/config.json`, создайте из `templates/zcode-config.json.template` — он подключает плагин `1c-dev-rules`.

### Шаг 4. Подсказать пользователю, что заполнить

После генерации явно скажите пользователю:

> Создан `AGENTS.md`. Заполните проектные секции (помечены `<!-- PROJECT: ... -->`):
> 1. **«Что это»** — тип и назначение конфигурации.
> 2. **«Где живёт бизнес-логика»** — ключевые объекты (2-5 главных документов/справочников).
> 3. **«Карты проекта»** — ссылки на архитектурные документы (если есть): карта движений, дерево подсистем, общие модули, реестр ADR (`docs/architecture/adr/` — архитектурные решения фиксируются на проектировании, скил `1c-solution-design`).
> 4. **«Технологии вокруг кода»** — IDE, тесты, CI.

### Шаг 5. Проверить

После заполнения проектных секций прогоните типовую задачу (например, «создай справочник») — убедитесь, что:
- Скилы `1c-dispatch-gate`, `1c-thin-triggers`, `1c-metadata` триггерятся.
- Префикс из `AGENTS.md` подхватывается.

## Что НЕ делать

- **Не удалять существующий `AGENTS.md`** без подтверждения пользователя. Если он есть — предложите дополнить/мигрировать, а не перезаписать.
- **Не заполнять проектные секции за пользователя** — карты проекта, бизнес-объекты знает только он. Сгенерируйте заглушки.
- **Не тащить в `AGENTS.md` всё содержимое карточек** — они в плагине. `AGENTS.md` — только процедуры/принципы + проектная специфика.
- **Не запускать повторно**, если `AGENTS.md` уже сгенерирован и заполнен.

---

## Миграция с самописной системы правил

Если в проекте уже есть своя система правил (`docs/standards-cards/`, `CLAUDE.md`, отдельные документы):

1. Прочитать существующие правила и сравнить с универсальными секциями шаблона.
2. Универсальные части (запросы, формы, транзакции, чек-листы) — **удалить из проекта**, они теперь в плагине.
3. Проектные части (карты объектов, каноничные чтения конкретных регистров, инциденты) — **оставить в проекте**, перенести в соответствующие секции нового `AGENTS.md`.
4. В новом `AGENTS.md` оставить ссылку на плагин и только проектную специфику.

## Детали (читать по необходимости)

- `templates/AGENTS.md.template` — заготовка `AGENTS.md` с универсальными секциями + заглушками
- `templates/zcode-config.json.template` — заготовка конфигурации ZCode
- `references/agents-sections.md` — полные тексты универсальных секций (два слоя кода, ParentConfigurations.bin, этапы работы, принципы эксперта, поисковые шаблоны)
