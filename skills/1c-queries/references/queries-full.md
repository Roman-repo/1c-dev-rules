> Полный список раздела — в [`standarts/std/queries.md`](../../standarts/std/queries.md).

## №729 — Общие требования к оптимальным запросам

**Критичность:** 🔴 Блокирующее

**Суть:** Запрос должен получать только нужные поля и строки. Не «всё, потом отфильтруем», а сразу узкий отбор. Используйте параметры, а не динамическую конкатенацию текста.

❌ **Неправильно:**
```bsl
Запрос.Текст = "ВЫБРАТЬ * ИЗ Документ.ЗаявкаНаРемонт";
// потом в коде фильтруем циклом по дате/организации
```

✅ **Правильно:**
```bsl
Запрос.Текст =
    "ВЫБРАТЬ Документ.Ссылка, Документ.Дата
    |ИЗ Документ.ЗаявкаНаРемонт КАК Документ
    |ГДЕ Документ.Дата МЕЖДУ &ДатаНач И &ДатаКон
    |   И Документ.Организация = &Организация";
```

🔍 Авто-проверка: `#bslls:ExtraFieldsInSelect`, `#bslls:UseLessQuery`
📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/729.md)
См. также: №656 (использование `*`), №655

## №655 — Соединения с вложенными запросами и виртуальными таблицами

**Критичность:** 🔴 Блокирующее

**Суть:** В `ИЗ` соединяйте только обычные таблицы. **Не соединяйте** напрямую вложенные подзапросы и виртуальные таблицы (`Остатки`, `СрезПоследних`) — сначала поместите их во временную таблицу, соединяйте уже её. СУБД не может оптимизировать план с ВТ «внутри» соединения.

❌ **Неправильно:**
```bsl
"ВЫБРАТЬ ...
|ИЗ Документ.АктОВыполненииЭтапаРабот КАК Акт
|   ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.Ремонты.Остатки(&Дата, ) КАК Ост
|   ПО Акт.ID_Ремонта = Ост.ID_Ремонта
|   ЛЕВОЕ СОЕДИНЕНИЕ (ВЫБРАТЬ ... ИЗ ...) КАК Вложенный
|   ПО ..."
```

✅ **Правильно:**
```bsl
"ВЫБРАТЬ ... ПОМЕСТИТЬ ВрОстатки ИЗ РегистрНакопления.Ремонты.Остатки(&Дата, );
|ВЫБРАТЬ ... ПОМЕСТИТЬ ВрДопДанные ИЗ (...);
|////////////////////////////////////////////////////////////////////////////////
|ВЫБРАТЬ ...
|ИЗ Документ.АктОВыполненииЭтапаРабот КАК Акт
|   ЛЕВОЕ СОЕДИНЕНИЕ ВрОстатки КАК Ост
|   ПО Акт.ID_Ремонта = Ост.ID_Ремонта
|   ЛЕВОЕ СОЕДИНЕНИЕ ВрДопДанные КАК Вложенный
|   ПО ..."
```

> 💡 **Пример из проекта:** главный запрос списка «Ремонты» рабочего места техспециалиста (`Forms/Форма/Form.form:6450`) нарушает этот стандарт 10 раз — см. [отчёт о производительности](../perf-reports/РабочееМестоТехническогоСпециалиста-Зависание.md).

🔍 Авто-проверка: `#bslls:InvalidNamesViewFunctions` (частично)
📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/655.md)
См. также: №733, №732

## №733 — Эффективное обращение к ВТ «Остатки» / «СрезПоследних»

**Критичность:** 🔴 Блокирующее

**Суть:** Всегда передавайте в виртуальную таблицу `Остатки(Дата, Отбор)` и `СрезПоследних(Дата, Отбор)` **оба параметра**. Без параметров СУБД разворачивает весь регистр до текущего момента — это главная причина «тормозящих» запросов.

❌ **Неправильно:**
```bsl
// нет даты, нет отбора — СУБД читает ВСЕ записи регистра
ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.НарядыПоРемонтам.СрезПоследних(, ) КАК Наряды
```

✅ **Правильно:**
```bsl
ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.НарядыПоРемонтам.СрезПоследних(
    &ДатаКонца, ОбъектРемонта В (&МассивОР)) КАК Наряды
```

⚠️ **Важно для ТОИР:** некоторые регистры периодические «по положению регистратора», и статус ремонта требует анализа интервала, а не среза на дату. В таких случаях `СрезПоследних` с датой **некорректен** — нужно предрасчётное решение (см. [архитектурное предложение](../perf-reports/РабочееМестоТехСпец-АрхитектурноеПредложение.md)). Правило применимо к регистрам, где срез на дату осмыслен.

🔍 Авто-проверка: `#bslls:VirtualTableCallWithoutParameters`
📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/733.md)
См. также: №657

## №732 — Запросы в динамических списках

**Критичность:** 🔴 Блокирующее

**Суть:** Динамический список — самый «горячий» запрос в форме: перевыполняется при каждом обновлении, у каждого пользователя. Поэтому:
- **Никаких** соединений с ВТ и подзапросами (см. №655);
- **Никаких** обращений через точку к реквизитам ссылок (`.Ссылка.Организация` — это неявное соединение);
- Минимум соединений вообще;
- Отборы через параметры динамического списка, а не через ГДЕ по вычисляемым полям.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/732.md)
См. также: №655, №733, №489

## №436 — Многократное выполнение однотипных запросов

**Критичность:** 🔴 Блокирующее

**Суть:** Не вызывать один и тот же запрос в цикле. Соберите массив значений, выполните запрос один раз с `В (&Массив)`, обходите результат.

❌ **Неправильно:**
```bsl
Для Каждого Стр Из Массив Цикл
    Запрос.Текст = "...ГДЕ ОбъектРемонта = &ОР";
    Запрос.УстановитьПараметр("ОР", Стр.ОбъектРемонта);
    Результат = Запрос.Выполнить();   // N запросов к БД
КонецЦикла;
```

✅ **Правильно:**
```bsl
Запрос.Текст = "...ГДЕ ОбъектРемонта В (&МассивОР)";
Запрос.УстановитьПараметр("МассивОР", МассивОбъектов);
Результат = Запрос.Выполнить();   // 1 запрос
```

🔍 Авто-проверка: `#bslls:QueryInLoop`
📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/436.md)

## №656 — Запрет `*` в `ВЫБРАТЬ`

**Критичность:** 🟡 Важно

**Суть:** Не использовать `ВЫБРАТЬ *`. Перечисляйте только нужные поля — это уменьшает трафик и устойчиво к появлению новых реквизитов.

🔍 Авто-проверка: `#bslls:ExtraFieldsInSelect`
📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/656.md)

## №658 — Эффективные условия в `ГДЕ`

**Критичность:** 🔴 Блокирующее

**Суть:** Условия в `ГДЕ` должны позволять СУБД использовать индексы. Избегайте в условиях:
- функций над полями (`Месяц(Дата) = 1` → фильтр не по индексу);
- арифметики над полями (`Колво - Резерв > 0`);
- `ПОДОБНО` с лидирующим `%` (`"%АБВ"` — индекс бесполезен, `"АБВ%"` — работает);
- неявного приведения типов (число сравнивается со строкой).

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/658.md)

## №657 — Обращения к виртуальным таблицам

**Критичность:** 🔴 Блокирующее

**Суть:** Дополнение к №733. Виртуальные таблицы (`Остатки`, `СрезПоследних`, `Обороты`) — это неявный вложенный запрос. Если ВТ используется в сложном запросе, выносите её во временную таблицу (№655) и соединяйте уже временную. Не вкладывайте ВТ в подзапросы.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/657.md)
См. также: №655, №733

## №438 — Проверка на пустой результат

**Критичность:** 🟡 Важно

**Суть:** Чтобы проверить, есть ли данные, не нужно получать все записи. Используйте `ВЫБРАТЬ ПЕРВЫЕ 1` + `Пустой()`, а не `Количество() > 0` или полную выборку.

❌ **Неправильно:**
```bsl
Если Запрос.Выполнить().Выгрузить().Количество() > 0 Тогда ...
// или
Если Запрос.Выполнить().Выбрать().Количество() > 0 Тогда ...
```

✅ **Правильно:**
```bsl
Запрос.Текст = "ВЫБРАТЬ ПЕРВЫЕ 1 1 КАК ЕстьДанные ГДЕ ... ";
Если НЕ Запрос.Выполнить().Пустой() Тогда ...
```

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/438.md)

## №787 — Вычисление количества записей

**Критичность:** 🟡 Важно

**Суть:** `Счётчик` (`COUNT(*)`) может быть тяжёлым, если СУБД вынуждена прочитать все строки. Если точное количество не нужно — избегайте его. Если нужно — СУБД сама оптимизирует, но только если нет тяжёлых условий и соединений.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/787.md)

## №412 — Упорядочивание результатов

**Критичность:** 🟡 Важно

**Суть:** `УПОРЯДОЧИТЬ ПО` — дорого. Если порядок не критичен для пользователя, не задавайте. Если критичен — упорядочивайте по индексированным полям. Не упорядочивайте по вычисляемым полям — СУБД делает full sort.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/412.md)

## №434 — `ОБЪЕДИНИТЬ` vs `ОБЪЕДИНИТЬ ВСЕ`

**Критичность:** 🟡 Важно

**Суть:** `ОБЪЕДИНИТЬ` (без `ВСЕ`) выполняет **неявное DISTINCT** — дорого и часто не нужно. `ОБЪЕДИНИТЬ ВСЕ` быстрее и сохраняет все строки. Используйте `ВСЕ` по умолчанию; без `ВСЕ` — только когда дубли действительно недопустимы.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/434.md)

## №415 — `РАЗРЕШЕННЫЕ` в запросах

**Критичность:** 🟡 Важно

**Суть:** `ВЫБРАТЬ РАЗРЕШЕННЫЕ` добавляет в запрос проверки RLS. Используйте осознанно: в запросах, где важно соблюсти права текущего пользователя. Не «на всякий случай» — это утяжеляет запрос.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/415.md)

## №535 — Округление в арифметике запросов

**Критичность:** 🟡 Важно

**Суть:** Округление в запросе (`ВЫРАЗИТЬ(... КАК ЧИСЛО(15,2))`) — это отсечение, а не банковское округление. Если важна корректность — округляйте на сервере в коде, не в запросе.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/535.md)

## №652 — Соответствие индексов и условий

**Критичность:** 🟡 Важно

**Суть:** Условия в `ГДЕ` должны попадать в существующие индексы таблицы. Если вы фильтруете по неиндексированному полю — СУБД делает full scan. Проверяйте план запроса; при необходимости — просите добавить индекс (через стандартные механизмы).

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/652.md)

## №654 — Разыменование ссылочных полей составного типа

**Критичность:** 🔴 Блокирующее

**Суть:** Обращение через точку к реквизиту ссылки составного типа (`Объект.Контрагент.Наименование`, где `Контрагент` может быть справочником или документом) — СУБД строит очень тяжёлый план с union по всем возможным типам. Избегайте; разыменуйте только после сужения типа.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/654.md)
См. также: №728

## №777 — Использование временных таблиц

**Критичность:** 🟡 Важно

**Суть:** Временные таблицы (`ПОМЕСТИТЬ Вр...`) — инструмент оптимизации сложных запросов: заранее отобранные данные кладутся в ВТ, затем к ней идут соединения. Использовать для:
- результатов виртуальных таблиц (№655);
- повторно используемых в запросе выборок;
- разыменований составных типов (№654).

ВТ удаляйте (`УНИЧТОЖИТЬ Вр...`) после использования.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/777.md)

## Мини-чек-лист по запросу (для ревью и самопроверки)

- [ ] В `ВЫБРАТЬ` только нужные поля, нет `*`
- [ ] Отборы в `ГДЕ` по полям таблиц-источников, не по вычисляемым
- [ ] Нет соединений с ВТ и подзапросами напрямую (№655)
- [ ] ВТ `Остатки`/`СрезПоследних` вызваны с параметрами даты и отбора (№733)
- [ ] Нет запросов в цикле (№436)
- [ ] Временные таблицы с префиксом `Вр`, уничтожаются после использования
- [ ] Для динамического списка — запрос максимально «плоский» (№732)
