# 1c-performance — производительность, серверные вызовы

> Каждая строка кода должна быть **быстрой**. Производительность — не «потом оптимизирую», а «сразу пишу эффективно».

## 🔴 №487 — Минимизация серверных вызовов и трафика

Каждый серверный вызов — это round-trip + сериализация. Группируйте операции: одна серверная процедура делает максимум работы, а не вызывается по разу на каждое поле формы.

❌ Три вызова на три поля → ✅ один вызов, возвращающий структуру.

## 🔴 №636 — Контекстный vs внеконтекстный сервер

`&НаСервере` (контекстный) — когда данные формы нужны. `&НаСервереБезКонтекста` — когда не нужны. Каждый round-trip с контекстом дороже.

## 🔴 №725 — Обращение через точку в цикле

`Стр.Документ.Организация` в цикле → неявный серверный вызов на каждую строку. Вынесите чтение до цикла (запросом или кэшем).

## 🔴 №489 — Динамические списки

- «Плоский» запрос (без ВТ в соединениях, без точек к ссылкам — №732).
- `АвтоОбновление = Истина` только если нужно; период не короткий.
- Для невидимых списков — `Ложь`.

## 🟡 №792 — Многократная запись регистров

Несколько записей в один регистр — одним набором, не по одной строке в цикле.

⚠️ **Исключение:** запись разных записей через `СоздатьМенеджерЗаписи` в цикле — каноничный паттерн для регистров с параллельной записью (очереди, логи). Перед обвинением — `grep` по каноничным модулям проекта.

## №496 — Чтение отдельных реквизитов объекта

Не `ПолучитьОбъект()` для 1–3 полей → `ОбщегоНазначения.ЗначенияРеквизитовОбъекта(...)` или запрос.

## №664 / №708 / №491 — Регистры и итогы

- Разделение итогов регистров накопления (№664).
- Разрешение итогов для периодических регистров сведений (№708).
- Влияние параметров сеанса и ФО на RLS (№491).

## №791 — Дополнительные индексы

Каждое условие `ГДЕ` должно попадать в индекс. Если поля нет в индексе — СУБД делает full scan.

## №659 / №661 — Блокировки

- Избыточные блокировки (№659) — не блокируйте больше нужного.
- Блокирующее чтение остатков в начале транзакции (№661) — источник deadlock'ов.

---

## Мини-чек-лист по производительности

- [ ] Серверные вызовы сгруппированы (№487)
- [ ] Внеконтекстный сервер где форма не нужна (№636)
- [ ] Нет обращений через точку в цикле (№725)
- [ ] Динамический список «плоский», без автообновления для невидимых (№489)
- [ ] Многократная запись — пакетная (№792)
- [ ] Чтение точечное, `ЗначенияРеквизитовОбъекта` вместо `.ПолучитьОбъект()` (№496)
- [ ] Условия `ГДЕ` попадают в индексы (№791)
- [ ] ФО / параметры сеанса кэшируются
