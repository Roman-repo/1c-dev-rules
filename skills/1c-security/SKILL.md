# 1c-security — права, RLS, безопасность

> Права доступа — самая «провальная» категория при создании новых объектов. Роли часто забывают, и объект становится невидимым для стандартных пользователей.

## 🔴 №532 — Роли для новых объектов и полей

Каждый новый объект метаданных (справочник, документ, регистр, **константа**) и каждое новое поле должны быть включены **минимум в одну роль** с осмысленными правами.

Не оставлять «все права всем» и не оставлять без ролей совсем — иначе объект будет недоступен или, наоборот, открыт всем.

**Проверка после создания объекта:**
```bash
grep -rl "Constant.<Префикс>Имя\|InformationRegister.<Префикс>Имя\|Catalog.<Префикс>Имя" Roles/
```
Должен вернуть ≥1 файл.

**Типовые наборы прав:**
- **Константа-настройка** → `Read` в роли базовых прав; `Read+Update` в роль администратора.
- **Регистр адресатов/настроек** → `Read+Update` (чтобы администратор мог заполнять); права на измерения — `View+Edit`.
- **Справочник/документ** → отдельные роли `Чтение…`/`ДобавлениеИзменение…` (как принято в проекте).

## 🔴 №485 — Привилегированный режим

`УстановитьПривилегированныйРежим(Истина)` — только для служебных операций, с обоснованием в комментарии. **Всегда парно** с `УстановитьПривилегированныйРежим(Ложь)` в `Попытка`/`КонецПопытки`. Не расширяйте видимость молча.

## 🔴 №737 — Проверка прав доступа

Права доступа проверяются через `ПравоДоступа(...)` перед операцией, не «выполняем и ловим отказ». Проверка — на сервере.

## 🟡 №689 / №455 — RLS

RLS-схемы (ограничение доступа на уровне записей) — соответствуют схемам доступа БСП. Не придумывайте свои схемы, используйте стандартные.

## 🔴 №770 — `Выполнить` / `Вычислить` с пользовательским вводом

`Выполнить(...)` / `Вычислить(...)` на сервере с пользовательским вводом — инъекция. Запрещено.

## 🟡 №521 — Привилегированные модули

Привилегированные общие модули — только для служебных целей (обновление ИБ, регламентные расчёты), с обоснованием. Не для бизнес-логики.

## 🟡 №488 — Стандартные роли

Используйте стандартные роли БСП (`БазовыеПрава`, `ПолныеПрава`, `АдминистраторСистемы`…) — не плодите кастомные без необходимости.

## Мини-чек-лист по безопасности

- [ ] Новый объект включён минимум в одну роль (№532)
- [ ] `УстановитьПривилегированныйРежим` — парный и обоснован (№485)
- [ ] Проверка прав через `ПравоДоступа`, не через «ловлю отказа» (№737)
- [ ] RLS-схемы соответствуют БСП (№689)
- [ ] Нет `Выполнить`/`Вычислить` с пользовательским вводом (№770)
- [ ] Привилегированные модули — только для служебных целей (№521)
