# 1c-reports — отчёты и печатные формы

> Отчёты на СКД — основной механизм. Печатные формы — через БСП «Управление печатью».

## 🔴 СКД (Система Компоновки Данных)

При создании/ревью отчёта на СКД — **откройте скил `1c-queries`** и его `references/dcs-design.md`. Ключевые правила:

- Тип набора данных — Запрос (не Объект без необходимости).
- Вычисления — протолкнуты в запрос/ресурс, не в вычисляемое поле.
- Параметры периодов ВТ — через параметры, не литералами.
- Программный override — через `ПриКомпоновкеРезультата` с `СтандартнаяОбработка = Ложь` ДО `Попытка`.
- Привилегированный режим — парный (`Истина`/`Ложь`) и обоснован.

📖 Полная карточка по проектированию СКД — скил `1c-queries` → `references/dcs-design.md`.

## №670 — Содержание отчёта

Отчёт должен быть самодокументируемым: имя, синоним, назначение — понятны пользователю. Варианты — для принципиально разных представлений, не для «фильтр по умолчанию».

## 🔴 №548 / №789 — Печатные формы

Печатные формы — через БСП-механизм «Управление печатью»:
- В модуле менеджера документа — `Печать(...)` с макетом.
- Регистрация — через `Справочник.ИдентификаторыОбъектовМетаданных` / настройки подсистемы БСП.
- Не пишите свою систему печати — используйте БСП.

## 🟡 Варианты отчётов БСП (№671/№673)

- Варианты — принципиально разные представления (по документам vs по контрагентам).
- Пользовательские настройки — минимальные; неиспользуемые — `Недоступен`.
- Размещение в подсистеме отчётов — через `ВариантыОтчетовПереопределяемый.НастроитьВариантыОтчетов`.

## Мини-чек-лист по отчётам

- [ ] Отчёт на СКД — запрос, а не Объект (если возможно)
- [ ] Вычисления протолкнуты в запрос/ресурс
- [ ] Программный override — `СтандартнаяОбработка = Ложь` до `Попытка`
- [ ] Печатные формы — через БСП (№548/№789)
- [ ] Варианты — принципиально разные, настройки минимальны
- [ ] Привилегированный режим в СКД — парный и обоснован
