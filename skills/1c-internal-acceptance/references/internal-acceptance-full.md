# Внутренняя приёмка: полный регламент

> Развёрнутые правила этапа «Внутренняя приёмка» (SKILL.md
> `1c-internal-acceptance`). Роль — разработчик в шляпе тестировщика.
> Вход — код + 02/04; выход — `05-internal-acceptance.md`.

---

## Подготовка данных прогона

| Тип данных | Зачем | Пример |
|---|---|---|
| «Стерильные» | Счастливый путь без шума | Новая заявка с заполненными полями |
| Граничные | Края диапазонов | Пустая категория; минимальная/максимальная дата; самая старая запись |
| «Грязные» | Отклонения | Недозаполненные объекты, дубли, данные от прошлых версий |
| Конкурентные | Одновременный доступ | Два пользователя меняют один объект |

Граничные данные берите из критериев успеха карточки (01): замеры «до/после»
проводятся на сопоставимом объёме, иначе сравнение бессмысленно.

## Что считать evidence

Evidence = то, что независимый проверяющий может перепроверить без автора:

- номер документа/записи и дата создания;
- скриншот с датой/временем (для UI-поведения);
- замер: инструмент, объём данных, результат (см. `1c-performance`,
  расследование через ТЖ — если критерий про скорость);
- имя теста и его результат (unit/BDD) — тест сам себе evidence;
- строка журнала регистрации (для ошибок/логирования).

«Проверял, работает» — не evidence.

## Порядок прогона

1. Счастливый путь целиком, шаг за шагом, по таблице 02.
2. Все отклонения.
3. Тесты из 04 (unit → BDD; падение — самовозврат класса A).
4. Замеры, заявленные в критериях (сравнение «до/после» по 03, секция
   «Производительность»).
5. Отклонения и ограничения — выписать в отчёт.

## Повторный прогон после возврата

- Класс A/D: перепроверяются затронутые шаги + шаги вокруг изменений;
  полный прогон — по решению рецензента ревью изменённого кода.
- Класс B: сценарий изменился (02 обновлён) — прогон по изменённым и новым
  шагам; если изменились критерии (04) — по изменённым строкам матрицы.
- В отчёте 05 указывается: «повторный прогон после возврата <дата>, охват:
  шаги №...». Старые строки отчёта не перезатираются — добавляются новые.

## Связь с матрицей трассировки (04)

Отчёт 05 — источник статусов для матрицы: ✅/❌ по каждой строке. Если строку
матрицы проверить не удалось (например, BDD-сценарий ещё не написан) — статус
«⚠️ не проверено, причина» и согласование с РП: сдавать строку вслепую нельзя.

## Сигналы качества этапа

| Сигнал | Интерпретация |
|---|---|
| Отклонения падают чаще счастливого пути | Проектирование веток было формальным — сообщить в 02 (кандидат на класс B) |
| Отклонения от спецификации > 2 | Спецификация писалась не по задаче — вернуться к 03 |
| Evidence нет на большинство строк | Отчёт фиктивный: этап «пройдён», но не выполнен |
