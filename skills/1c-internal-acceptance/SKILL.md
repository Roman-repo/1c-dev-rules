# 1c-internal-acceptance — Внутренняя приёмка: против сценария, не по памяти

> Роль этапа — **разработчик в шляпе тестировщика**. Смена шляпы = смена точки
> зрения: тестировщик проверяет **против сценария** (`02-execution-scenario.md`),
> а не «помнит, что код должен работать». Выход — **Отчёт внутренней приёмки**;
> задача с красным отчётом на код ревью и внешнюю приёмку не идёт.

## Вход этапа

- Код с DoD разработки: самопрогоны `1c-thin-triggers`, `1c-code-review`
  (как чек-лист самопроверки); для метаданных — `validate-new-object.sh`
  без необъяснённых FAIL. Статусы прогонов фиксируются в шапке отчёта 05.
- Артефакты проектирования: 02 (сценарий), 04 (критерии приёмки).

## Процедура

1. **Перечитайте сценарий до запуска.** Свежий взгляд: сначала ожидание,
   потом действие — не наоборот.
2. **Счастливый путь по шагам.** Каждый шаг: «ожидание (из 02) → факт → ✅/❌ →
   evidence». Evidence — номер документа/даты, скриншот, замер: то, что
   можно перепроверить.
3. 🔴 **Отклонения — обязательно.** Пустые данные, отмены, отказ
   прав — именно они чаще всего не проверяются и всплывают у приёмщика.
4. **Тесты из матрицы 04** — заявленные unit/BDD проверки прогнаны,
   результат и имена тестов зафиксированы. Критерий, упавший ❌ в двух
   раундах протокола 06, проверяется автотестом — падение теста = красная
   строка этого отчёта (правило `1c-delivery-gate` → `rework-rules`).
5. **Отклонения от спецификации** — перечислить каждое + обоснование.
   Отклонение без обоснования — дефект; с обоснованием — согласовать с РП
   **до** сдачи (и отразить в 03).
6. **Известные ограничения** — явно в отчёт: «работает, но при объёме >100 000
   строк выполняется N секунд». Ограничение, обнаруженное приёмщиком, —
   замечание; заявленное заранее — согласованная особенность.
7. 🔴 **Красное — самовозврат.** Любой ❌ шага или упавший тест: этап
   «Разработка» (класс A), исправить, прогон повторить. Сдавать с «потом
   довесим» запрещено.

## Статический прогон (нет живой базы)

Если живая база/стенд недоступны, внутренняя приёмка выполняется **статически**:

- Каждый шаг сценария верифицируется по коду и метаданным: evidence —
  `файл:строка` и результат grep/xmllint/структурной сверки (параметры
  макета ↔ заполнение, &X ↔ УстановитьПараметр, области ↔ ПолучитьОбласть).
- Статус шага помечается «✅с» (= «✅ (статич.)» в артефактах до 0.13.0);
  статически не проверяемые шаги помечаются «⏳» и передаются на внешнюю
  приёмку приёмщику. Алфавит статусов матрицы 04 — `1c-solution-design`.
- Режим и его причина фиксируются в поле «Среда» отчёта 05; ограничение
  «живой прогон не выполнялся» — обязательно в «Известных ограничениях».
- 🔴 Статический прогон не заменяет живой: приёмщик на внешней приёмке
  проходит ⏳-шаги лично; при расхождении — класс A/B по общей схеме.

## Антипаттерны

| Антипаттерн | Чем оплачивается |
|---|---|
| Проверка «как писал — так и работает» | Слепые зоны автора = находки приёмщика |
| Отклонения «рискнул, работает» | Класс B с приёмки за то, что стоило 5 минут здесь |
| Отчёт без evidence | Спор о фактах на повторной приёмке |
| Отклонения от спецификации замалчиваются | Приёмщик находит сам — доверие к отчётам падает |
| Красный отчёт сдан «чтобы не задерживать» | Возврат дороже паузы |

## Артефакт-выход

`05-internal-acceptance.md` — Отчёт внутренней приёмки. Создаётся копированием
`references/internal-acceptance-report-template.md` в каталог доставки задачи.
Статусы из отчёта переносятся в колонку «Статус 05» матрицы трассировки (04);
алфавит статусов — `1c-solution-design` (✅ / ✅с / ⏳ / ❌ / n/a).

Чистый 05 — передача задачи на следующий этап: **код ревью**
(`1c-code-review`, артефакт `05a-code-review.md`), затем внешняя приёмка.
Строка «Входные проверки разработки» в шапке 05 остаётся фиксацией
самопрогонов этапа «Разработка» (гейт 4→5) — решением Ревьюера она не является.

## Мини-чек-лист (DoD этапа)

- [ ] Каждый шаг основного потока пройден с фиксацией ожидание/факт/evidence
- [ ] Все отклонения пройдены
- [ ] Заявленные в 04 тесты прогнаны, результаты зафиксированы
- [ ] Отклонения от спецификации перечислены и обоснованы (согласованы с РП)
- [ ] Известные ограничения зафиксированы
- [ ] Красных строк нет; статусы перенесены в матрицу 04
