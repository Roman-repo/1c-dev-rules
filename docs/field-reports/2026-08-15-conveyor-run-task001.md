# Полевой отчёт — прогон конвейера разработки на задаче TASK-001 (0.11.1)

> 6-й полевой тест, первый прогон **конвейера разработки** (скилы этапов 1–6).
> Задача: компактная печатная форма согласования для `торо_ЗаявкаНаРемонт`
> (toir2, EDT). Полный цикл: Планирование → Проектирование → Разработка →
> Внутренняя приёмка → Внешняя приёмка (отложена) → Релиз (черновик).
> Артефакты задачи: `toir2/docs/delivery/TASK-001/01…06` +
> `_releases/2.0.27.0-draft/`.

## Контекст прогона

- Живая база 1С в сессии недоступна: код и макет (XML) правились вслепую,
  интерактивная приёмка перенесена инициатору.
- Конвейер выдержал паузу честно: 06-протокол «отложено», релиз — черновик.

## Находки (формат отчёта об отклонениях)

### 1. [Скрипт validate-new-object.sh / X5] — &&Маркер принят за параметр запроса

Пример: `toir2 …/Forms/ФормаДокумента/Module.bsl:2491` — `|&&БлокОтбора`,
заменяется целиком `СтрЗаменить` (:2621-2626); X5 сообщил
«есть в &X, нет в УстановитьПараметр: БлокОтбора» → ложный FAIL.
(«Валюта» из `ПечатьЗаявки:280` — истинное срабатывание: мёртвая установка
параметра в существующем коде, не находка.)

Предложение: вычищать `&&Имя` (экранированный маркер подстановки) до
извлечения токенов `&Имя`. — **Исправлено в этом PR.**

Класс: 🟡 ложное срабатывание

### 2. [1c-external-acceptance] — нет легального статуса «отложено»

Пример: приёмщик ответил «пока не могу прогнать» (нет живой базы). Скил
предлагал только «принято / возврат»; паузу конвейера пришлось изобретать
самостоятельно (статус в 06, правило возобновления `.r1`).

Предложение: узаконить статус протокола «отложено» + правило «переход на
Релиз запрещён, возобновление — новый протокол .r1». — **Исправлено.**

Класс: 🟢 пробел в покрытии

### 3. [1c-release] — нет правила черновика релиза при отложенной приёмке

Пример: железное правило «только с протоколом "принято"» не оставляет места
для подготовки релизных артефактов при длинном цикле сборки; черновик
`2.0.27.0-draft` со статусом «не включять в поставку» — самодеятельность.

Предложение: исключение для «отложено»: артефакты черновиком
`_releases/<версия>-draft/`, задача — в «Отбор отклонён». — **Исправлено.**

Класс: 🟢 пробел в покрытии

### 4. [1c-internal-acceptance] — не описан статический прогон без живой базы

Пример: все шаги 02 верифицировались по коду (evidence `файл:строка`,
grep/xmllint-сверки), интерактивные переданы внешней приёмке; нотация
«✅ (статич.) / ⏳ интерактивно» изобретена на месте.

Предложение: секция «Статический прогон»: правила evidence, пометки,
обязательная фиксация режима и ограничения в 05. — **Исправлено.**

Класс: 🟢 пробел в покрытии

### 5. [1c-solution-design / шаблон 04] — критерии приёмки из альтернативных потоков

Пример: КП 6-7 (пустая заявка, нет цен) происходят из потоков 3а/3б, а не из
критериев успеха 01 — по старому правилу требовалась запись в историю
изменений как «согласованное уточнение».

Предложение: второй легитимный источник — альтернативные потоки 02, пометка
«[АП]» в строке матрицы. — **Исправлено.**

Класс: 🟢 пробел в покрытии

### 6. [1c-metadata / metadata-xml] — нет карточки по макетам Template.mxlx

Пример: индексация форматов (с 1, 0 — встроенный) и шрифтов (с 0), структура
rowsItem/namedItem/merge, различие `<parameter>` vs `[Имя]` в
`fillType=Template` — всё выводилось эмпирически по образцу ПФ_MXL_Заявка;
ошибка индексации даёт тихо чужие шрифты/ширины.

Предложение: §8 «Макеты печатных форм Template.mxlx» с инвариантами MX1-MX5
и grep-сверками. — **Исправлено.**

Класс: 🟢 пробел в покрытии

### 7. [1c-queries / №436] — не описано исключение «срез на дату строки»

Пример: расчёт стоимости ремонта берёт цены `СрезПоследних(&Дата, …)` на
`ДатаНачала` каждой строки ремонта — дата это скалярный параметр ВТ, один
запрос на все строки невозможен; цикл запросов — канон проекта (ПечатьЗаявки),
но №436 его запрещает без оговорки.

Предложение: явное исключение в карточке №436: обоснование комментарием,
пакетный запрос на строку, фиксация в 03. — **Исправлено.**

Класс: 🟢 пробел в покрытии

## Позитивные подтверждения (не отклонения)

- `1c-planning`: интервью-чеклист снял противоречие постановки («переделать
  существующую» + «не трогаем смету» → «добавить вторую форму») до старта
  проектирования — ровно тот случай, ради которого этап существует.
- Конвейер в целом: шесть этапов прошли без потери артефактов; DoD-гейты
  сработали как контрольные точки (на гейте 1→2 поймано противоречие,
  3→4 — толчок к исправлению 9-параметровой процедуры).

## Черновые заметки на будущее (не в этот PR)

  запросах ВТ умирают сами; уточнить формулировку, чтобы не плодить лишние
  `УНИЧТОЖИТЬ`.
- Шаблон 05: колонка «Статус» в таблицах потоков рассчитана на ✅/❌ — после
  узаконивания «✅ (статич.)/⏳» обновить шаблон.
