# ADR-002: Диаграмма метаданных — представление, не проверка

- **Статус:** Принято (решения инициатора №2/№4 по issue #96, 2026-09-06)
- **Дата:** 2026-09-06
- **Автор:** функциональный архитектор (ИИ), утвердил: сопровождающий плагин (Оркестратор)
- **Задача-источник:** issue #96 «Добавить диаграммы для метаданных»

## Контекст

Этапы 1–2 конвейера (планирование/проектирование) держат картину связей
объектов текстом: таблица «Кросс-влияние» в 03 заполняется ручным grep по
`.mdo`. Impact-анализ неполон, Оркестратор согласует пакет без картины
целого, новому участнику нечего посмотреть. Источник связей уже оцифрован —
XML EDT-выгрузки содержит декларативные рёбра (`<registerRecords>`,
`<type><types>`, `<content>`, `<owners>`), и по ним детерминированно
строится Mermaid-граф. Вопрос — куда положить генератор и чем диаграмма
является в конвейере.

## Варианты

| № | Вариант | Плюсы | Минусы |
|---|---|---|---|
| 1 | Правила/режим в `metadata_scan.py` (слой проверок) | один CLI с индексом дерева | слой — про находки и exit-коды; диаграмма — не находка: смешение «проверка/представление» размывает семантику слоя и его счётчики покрытия |
| 2 | Ветка в `bsl_ls_analyze.py` (обёртка ревью) | рядом с артефактами ревью | диаграмма нужна на проектировании (этап 2), до и вне ревью; обёртка — Java-мир с чужими приоритетами |
| 3 | Отдельный скрипт `metadata_diagram.py` поверх `import metadata_scan` (переиспользует `load_object`/`diff_paths`/XML-хелперы; свой индекс рёбер с кэшем по паттерну `Context`) | диаграмма — артефакт разработки `diagrams/` без номерной семантики конвейера (`delivery_tools` не расширяется); ADR-001 не нарушен — сканер не меняется; без Java | третий скрипт в `scripts/`; индекс рёбер — свои данные, которых в индексе слоя нет (кэш отдельным файлом) |
| 4 | URL-сервисы диаграмм (draw.io/gliffy) | «богатый» редактор | вне git: не диффается, не рендерится на GitHub, внешний источник истины (отклонено решением №1) |

## Решение

Вариант 3. `scripts/metadata_diagram.py` — генератор Mermaid-диаграмм:
артефакт разработки `docs/delivery/<ЗАДАЧА>/diagrams/metadata-r<N>.md`
(ссылка из 03), НЕ номерной артефакт конвейера — `delivery_tools`
не расширяется, вердикты и exit-коды этапа «Код ревью» не затрагиваются.
Переиспользование через import (как обёртка у слоя): свой обход дерева НЕ
пишется; исключение — индекс рёбер с кэшем по mtime-хэшу, данных для
которого в индексе слоя нет. Детерминированность бит-в-бит: тот же дифф →
тот же файл, дата среза — от коммита REF или mtime входов, не от стеночных
часов.

## Последствия

**Стало проще / лучше:**
- impact-анализ 03 собирается командой, картина целого — на согласовании
  (04a) и ревью (05a);
- границы честно в легенде каждой диаграммы: записи регистров из кода и
  связи через запросы не видны — это декларативный срез `.mdo`;
- отдельная точка роста: формы (`.form`) и ER-уровень реквизитов — будущие
  эпики без риска для слоёв проверки.

**Стало дороже / нельзя:**
- `scripts/` +1 скрипт; индекс рёбер кэшируется отдельным файлом в общем
  `--cache-dir` (формат версионируется `EdgeIndex.VERSION`);
- таблица «Кросс-влияние» 03 и диаграмма — разные роли (что проверяем vs
  картина): правило «ссылка вместо пересказа» держится шаблоном 03 и скилом;
- состав подсистем — кластер, а не impact-ребро: участвует только когда
  подсистема сама в области (иначе диаграммы тащат сотни узлов группировки).
