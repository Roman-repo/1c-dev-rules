# Сценарий исполнения — META-001: Metadata-слой ревью по git-диффу

**Источник:** карточка задачи `01-task-brief.md` (критерии успеха № 1–4)

**Участники (роли процесса):**
- Разработчик (Исполнитель) — правит XML метаданных вслепую (без EDT), запускает слой, исправляет находки
- Слой metadata_scan (Система) — `scripts/metadata_scan.py`, детерминированные проверки `.mdo`/`.rights`/`Configuration.mdo` из диффа
- Ревьюер — этап 6 «Код ревью», переносит находки слоя в лист 05a

**Предусловия:** репо с EDT-выгрузкой (`src/`: `.mdo`, `.rights`, `Configuration.mdo`); git доступен (для `--diff`); python3 ≥ 3.9 только стандартная библиотека (Java НЕ нужна — в отличие от слоя BSL LS); правки XML задачи ещё не импортированы в EDT (регламент «вслепую»).

**Постусловия:** отчёт слоя детерминирован (одинаковый вход → одинаковые findings); отчёт чист по 🔴 (exit 0); 🟡/🟢 правятся или обосновываются в 05a; находки несут ключ каталога/локальный ключ, № стандарта и «как правильно».

## Счастливый путь

| № | Роль | Шаг (что делает) | Триггер (когда) | Описание | Результат шага |
|---|---|---|---|---|---|
| 1 | Разработчик | Завершает правки XML объекта | Этап «Разработка», метаданные задачи готовы к самопроверке | Правит `.mdo`/`.rights`/`Configuration.mdo` вслепую | Git-дифф задачи содержит metadata-источники |
| 2 | Разработчик | Запускает слой на диффе | Шаг 1 завершён | `python3 scripts/metadata_scan.py <вход> --diff <REF> --src-root <src> [--report ФАЙЛ] [--coverage-report]` | md/json-отчёт находок; exit 0/1 |
| 3 | Слой | Применяет правила к источникам из диффа | Шаг 2 | Парсит `.mdo`/`.rights`/`Configuration.mdo` (+ кросс-файловые проверки по `--src-root`) | Каждая находка: ключ + № стандарта + «что не так» + «как правильно» |
| 4 | Разработчик | Исправляет 🔴-находки и повторяет прогон | В отчёте есть 🔴 | Правит по колонке «как правильно»<br>Повторяет прогон (r2, r3…) | Отчёт чист по 🔴, exit 0; раунды в `code-review/` задачи |
| 5 | Разработчик | Проверяет объект старым входом | Шаг 4 завершён | `bash scripts/validate-new-object.sh <объект>` | Скрипт вызывает metadata-слой для `.mdo`/`.rights`-проверок + сам делает формовые (F3/F4/F10/X1/X2/X3/X4/X15); единый вердикт |
| 6 | Ревьюер | Включает metadata-находки в лист 05a | Задача на этапе 6 | Проходит чек-лист + каталог checkbsl (metadata.md)<br>Ссылается на ключи/№ из отчёта слоя | 05a со ссылками на ключи; решение «Одобрено»/«Доработать» |

## Отклонения

### 1а. XML-файл не разбирается (битый/незакрытый)

| № | Роль | Шаг | Триггер | Описание | Результат |
|---|---|---|---|---|---|
| 1а.1 | Слой | Пропускает файл с WARN | Ошибка парсинга ET | `WARN: файл не разобран — сверьте вручную` | Остальные файлы проверяются; молчаливого «всё ок» нет |

### 2а. Тип объекта не распознан (каталог вне таблицы типов)

| № | Роль | Шаг | Триггер | Описание | Результат |
|---|---|---|---|---|---|
| 2а.1 | Слой | Перечисляет пропущенное | Тип не входит в таблицу соответствия | Явный список неприменимых кросс-файловых проверок (наследие TYPE_UNKNOWN) | Пользователь знает, что НЕ проверено; exit только по реальным 🔴 |

### 3а. Нет `--src-root` / Configuration.mdo / Roles/

| № | Роль | Шаг | Триггер | Описание | Результат |
|---|---|---|---|---|---|
| 3а.1 | Слой | Пропускает кросс-файловые проверки | Источник контекста недоступен | Каждое пропускание — WARN | Внутрифайловые проверки выполнены; пропускания видимы |

### 4а. Ложное срабатывание («не баг»)

| № | Роль | Шаг | Триггер | Описание | Результат |
|---|---|---|---|---|---|
| 4а.1 | Ревьюер | Подавляет находку | Решение «не баг» в 05a | `review_suppress.py add suppress.json <Ключ> <файл> --reason "…"` → повтор с `--suppress` | Находка не выводится, показана счётчиком «Подавленные» |

### 5а. В диффе нет metadata-источников (только `.bsl`)

| № | Роль | Шаг | Триггер | Описание | Результат |
|---|---|---|---|---|---|
| 5а.1 | Слой | Сообщает об отсутствии источников | Дифф-фильтр дал 0 файлов `.mdo`/`.rights`/`Configuration.mdo` | Сообщение «metadata-источников в диффе нет» | exit 0; петля продолжает работу слоёв 1–2 |
