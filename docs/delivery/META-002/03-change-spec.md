## Дизайн

### Вызов слоя и конвертация находок

`run_metadata(ref_or_paths, src_root, cache_dir)` в обёртке:

- дифф-режим: `meta.diff_paths(ref)` (свой git-фильтр `.mdo`/`.rights`,
  `core.quotepath=off` уже внутри); пусто → слой молча пропускается (1а);
- режим путей: входы передаются `meta.collect_mdo` как есть (он берёт `.mdo`
  из файлов/каталогов, `.rights`-входы легальны);
- `src_root`: явный `--src-root` обёртки; иначе `meta.infer_src_root` (по
  объектам); для BSL LS семантика `--src-root` не меняется;
- `meta.scan(objects, ctx, entries=[])` — подавления НЕ здесь (единая точка
  в обёртке);
- конвертация `meta.Finding` → `scan.Finding` + extra: `section="metadata"`
  для каталогных ключей, `extra = {docs: карточка docs.checkbsl.org/checks/
  metadata/<Ключ>/ или "" для локальных, message: detail (что не так),
  ls_code: "слой метаданных (metadata_scan)", ls_severity: ""}` — метка слоя
  видна в отчёте и json (цель 01).

### Слияние

Обобщение `merge_layer1` → порядок приоритета metadata → слой 1 → BSL LS,
дедуп по (ключ, абсолютный путь, строка) — как сейчас; пути нормализуются
до абсолютных (слой 1 уже так делает). `merge_layer1` сохраняется как
обёртка над общим механизмом (тесты не ломаются).

### Дифф-режим без .bsl (отклонение 2а)

Сейчас пустой `scan.diff_files` даёт ранний выход «чисто» — metadata-слой
не запускался бы. Новый порядок: сначала `meta.diff_paths`; если `.bsl`
нет, а `.mdo` есть — java-прогон не выполняется, отчёт и exit по metadata;
нет ни того, ни другого — прежний «чисто», exit 0.

### Кэш индекса обхода (в `metadata_scan.py`)

`Context(src_root, objects, cache_dir=None)`:

- ключ — sha256 обхода дерева (путь/размер/mtime, как `cache_key` обёртки;
  чтение содержимого НЕ хэшируется — дорого);
- значение — сериализованный индекс `{uuid_files, rights_tokens,
  subsystem_hits}` (+ флаги have_roles/have_subs и `skipped`);
- несовпадение хэша или битый файл → индекс строится обходом и перезаписывает
  кэш (кэш никогда не источник истины);
- CLI: `--cache-dir DIR` (тот же смысл, что у обёртки); обёртка передаёт
  свой `--cache-dir`. Файлы кэша — разные пространства имён (префикс имени).

### Счётчик покрытия

`coverage_stats()` дополняется: `meta_layer` = каталогные ключи CHECKS ∩
harvest (16), `combined` = слой1 ∪ слой2 ∪ meta_layer. Контрольный пересчёт
на дереве main (2026-09-04): пересечение meta ∩ слой2 = 2 ключа
(`MetadataNameLongerThan`, `SameMetadataNames`), meta ∩ слой1 = 0 →
**combined 135 → 149/322 = 46,3%; секция metadata 4/32 → 18/32**. Точное
число воспроизводит счётчик; README/ARCHITECTURE/докстринг синхронизирует
тест-замок (обновление ожидаемых строк — в составе задачи). `--coverage-report`
печатает строку metadata-слоя и «Вместе (1 ∪ 2 ∪ metadata)».

### CLI и выходы

- `--no-merge-metadata` — отключить слой (критерий 3 из 01);
- `--merge-metadata FILE` — готовый json `metadata_scan.py --format json`
  (паритет с `--merge-scan`);
- `--cache-dir` — теперь кэширует и BSL LS-отчёт, и metadata-индекс;
- exit: 0/1/2 — без изменений (🔴 любого слоя → 1); 3 — дополнена подсказка:
  без Java доступны ОБА слоя по отдельности (`checkbsl_scan.py`,
  `metadata_scan.py`);
- шапка `--report`: «… + слой метаданных (metadata_scan.py, слито)» — по
  образцу строки слоя 1.

## Нефункциональные требования

| Категория | Требование |
|---|---|
| **Совместимость версий** | python ≥ 3.9, stdlib; standalone-CLI `metadata_scan.py` без `--cache-dir` ведёт себя как раньше (флаг опционален); json/md-форматы обёртки — обратно совместимы (расширяются полями) |
| **Объёмы и нагрузка** | Без кэша: +≈9,7 с на дереве toir2 к прогону обёртки (замер 05 META-001). С `--cache-dir`: повторная итерация петли ≤2 с (базлайн: 0,3 с кэш BSL LS PR #71 + 9,7 с metadata-обход без кэша, 05 META-001, 2026-09-04) |

| **Отказоустойчивость** | Кэш битый/повреждён → обход заново (не источник истины); ошибка слоя → exit 2 с диагностикой; `--no-merge-metadata` — аварийное отключение ветки |
