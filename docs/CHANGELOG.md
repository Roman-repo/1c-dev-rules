## [0.10.0] — 2026-08-15

### Добавлено

- **`validate-new-object.sh`: X15 — анализ `queryText` динамических списков в формах** (кейс E', пробел E'-1). До: X2/X3/X4/F10 проверяли структуру форм, но текст запроса ДС скрипт не читал — соединения с ВТ «Остатки»/«СрезПоследних» напрямую (№655/№732 — блокирующие в самом «горячем» запросе формы) не ловились. Теперь в той же Python-проходке на форму: СОЕДИНЕНИЕ с ВТ или подзапросом `(ВЫБРАТЬ…)` → FAIL; ВТ без параметра даты → WARN (№733, актуальный срез бывает осознанным); `ОБЪЕДИНИТЬ` без `ВСЕ` → WARN (№434). Разыменования через точку (№732) не проверяются — эвристика даёт ложные срабатывания на таблицы-источники, остаётся ручной grep. Негативная верификация: вендорская `ФормаЭлемента` `торо_ОбъектыРемонта` — пойманы оба соединения с ВТ `СрезПоследних` (Form.form:31342, 35226), оба «ОБЪЕДИНИТЬ без ВСЕ», обе «ВТ без даты»; позитивная: ФормаМониторинга с явным ЛЕВОЕ СОЕДИНЕНИЕ к обычной таблице — PASS, ложных срабатываний нет.

Обратное (объявлен, но не в запросе) — INFO: параметр может использоваться в выражениях/настройках. Разбор с явным namespace схемы: `dcscor:parameter` из настроек — другой namespace, совпадение по локальному имени путало бы ссылки с объявлениями.
