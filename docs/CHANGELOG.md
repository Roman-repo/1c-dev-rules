## [0.3.0] — 2026-08-11

Третий релиз: закрыт главный пробел набора — **тестирование**. Разведка репозитория [Desko77/claude-code-skills-1c](https://github.com/Desko77/claude-code-skills-1c) (MIT) показала, что v8std не выделяет тестирование как стандарт — это ниша инструментов (YaXUnit, Vanessa Automation). Добавлен скил по практике этих инструментов; заимствованы идеи и шаблоны (аттрибуция в карточке).

### Добавлено

- **Новый скил `1c-testing`** (22-й по счёту) + `references/testing-full.md`:
  - **YaXUnit** — unit-тесты серверной бизнес-логики: шаблон `Тест<Функция>_<Сценарий>`, assertion API `ЮТест.ОжидаетЧто(...).Равно(...)`, примеры happy path и error case.
  - **Vanessa Automation** — BDD-сценарии на Gherkin (`Функционал:`/`Сценарий:`/`Дано`/`Когда`/`Тогда`), критерий выбора BDD vs unit.
  - **Типология кейсов** — 4 типа на каждую функцию: happy / edge / error / boundary.
  - **Цели покрытия** — таблица (экспортные функции 100%, бизнес-логика 90%, утилиты 80%, UI 70%, общее 80%).
  - **Arrange/Act/Assert** как главное правило структуры любого теста.
- **`1c-dispatch-gate`** — добавлена маршрутизация на `1c-testing`: новая строка в гейт-чек-листе (§1) и в таблице A по типу работы (§2).

### Изменено

- **`1c-extensions` → `references/extensions-cfe.md`** усилен двумя граблями ролей расширения (платформа 8.3.27+), заимствованными из [Desko77/1c-extension-patterns](https://github.com/Desko77/claude-code-skills-1c/blob/main/rules/1c-extension-patterns.md) (MIT):
  - **`Enum.*` в `Rights.xml`** ломает `LoadConfigFromFiles -Extension` на 8.3.27; EDT 2026.1 может генерировать такие записи сам — проверяйте `git diff` и вычищайте.
  - **Двухпроходная загрузка роли** — если в одном экспорте новые объекты + роли на них, загрузка может зависать на резолве прав; обход: первый проход без `Roles/`, второй — полностью.
- **README** — счётчик скилов 21 → 22, references 28 → 29; `1c-testing` добавлен в категорию «💻 Код».

### Честно о разведке

Изначальная разведка двух репозиториев (Desko77 и Arman-Kudaibergenov) объявила «3 темы-пробела»: тестирование, асинх/Ждать, CFE-паттерны. При проверке наших карточек выяснилось, что **асинх (`1c-async`, 209 строк) и CFE (`1c-extensions`, 223 строки) уже полностью покрыты** — разведка опиралась на обзор агента без сверки с нашими файлами. Реальный пробел остался один — тестирование. В этот релиз вошёл только он плюс 2 точечные грабли в extensions.

## [0.2.1] — 2026-07-26

Усиление `1c-code-review` по образу плагина [Unica](https://github.com/IngvarConsulting/unica) (Ingvar Consulting, LGPL-3.0). Идеи рубрикатора high-risk patterns и формата вывода ревью адаптированы под структуру v8std; контент оригинальный.

### Добавлено

- **`1c-code-review` → секция 8 «High-risk patterns»** — рубрикатор из 9 категорий, которые проверяются всегда, независимо от типа изменённого объекта (границы транзакций, запрос в цикле, контекст сервер/клиент, привилегированный режим, избыточные права, фоновые задания, внешние вызовы, временные файлы, молчаливый перехват). Каждая категория связана со стандартом v8std и с раскрытием в секциях 1–7.

### Изменено

- **`1c-code-review` → «Шаблон комментария к MR»** переработан:
  - зафиксированы принципы вывода: findings first, отсортированы по серьёзности; «не переписывай код во время ревью, если не попросили»; каждое замечание заземлено в путь+строку;
  - структура одного finding — 5 полей: `Severity · Стандарт · Path · Issue · Impact · Fix`;
  - расширенный пример сгруппированного вывода (блокирующие/важно/рекомендации + открытые вопросы + краткое резюме).

## [0.2.0] — 2026-07-25

Второй релиз: зрелость open-source + инструментирование. validate_skills.py научился видеть ссылки «наружу» (вскрыл ~60 мест проектной специфики ТОИР в карточках); добавлены тесты, CI, CONTRIBUTING. Карточки полностью обезличены до универсального состояния.

### Добавлено

- `scripts/validate_skills.py` — автопроверка структуры скилов (без зависимостей, только stdlib). Проверяет: frontmatter, `name`=каталог + kebab-case + префикс `1c-`, `description` ≤1024 (warn >250), `license: MIT`, тело ≤500 строк, отсутствие проектной специфики (`торо_`/`гкс_`/`Project/Toir`), наличие ссылок на `references/*.md` с учётом cross-skill **и** относительных markdown-ссылок «наружу» (в `std/` и cross-skill между карточками) с умным 3-уровневым резолвингом. Exit code: 0/1.
- `tests/` — юнит-тесты валидатора на stdlib `unittest`: 3 fixture-скила (эталон/сломанный/без-license) + интеграционный тест на реальных `skills/` (11 тестов, ~0.04 с).
- `.github/workflows/validate.yml` — CI на push/PR: гоняет валидатор и тесты (Python 3.11 на ubuntu-latest). Битая структура не попадёт в `main`.
- `CONTRIBUTING.md` — гайд для контрибьюторов: как добавить скил, правила оформления (универсальность, ссылки, версии), синхронизация с upstream.
- `.github/PULL_REQUEST_TEMPLATE.md` — чек-лист PR (CI зелёный, локальная проверка, универсальность, README/CHANGELOG обновлены).
- `.github/ISSUE_TEMPLATE/` — шаблоны `bug_report.yml` (under/over-trigger, устаревшее правило, битая ссылка) и `feature_request.yml` + `config.yml` (вопросы → Discussions).
- `SECURITY.md` — политика безопасности (поверхность атаки минимальна: нет рантайм-кода, только `.md` и CI-линтер; ответственное раскрытие через e-mail).

### Изменено

- **Зачистка проектной специфики ТОИР в 15 reference-карточках + 2 SKILL.md + 1 template** (~60 правок). Валидатор вскрыл: ссылки на `../../CLAUDE.md` (файл проекта toir2), на `../perf-reports/...` (отчёты toir2), блоки «Пример из проекта» с `Module.bsl:N`/`Forms/Форма/Form.form:6450`, «Важно для ТОИР», «инцидент Б6/Б7», конвенцию с примерами `РемонтыСервер`. Удалено/обобщено до нейтральных примеров (`Документ.РеализацияТоваровУслуг`, `ТоварыСервер`).
- **15 битых ссылок `standarts/std/` → `../../../std/`** во всех 14 reference-файлах (каталог называется `std/`, не `standarts/std/`; глубина — 3 уровня вверх). Наследие переноса из toir2.
- **Cross-skill ссылки** (~25 мест) приведены к единому виду «скил `1c-<имя>`» вместо битых `../<name>.md`/`./<file>.md` (скилы — каталоги, не `.md`-файлы).
- `docs/ARCHITECTURE.md` — поправлены устаревшие «19 скилов» → 21, статусы этапов 2/3 (завершены).
- `1c-project-bootstrap` — примеры параметров обезличены (убраны `торо_`/`гкс_`/`Project/Toir/src/` из таблицы; `<Префикс>Ремонты` → `<Префикс><Домен>`).
- Версия `0.1.0 → 0.2.0` в `plugin.json` и `marketplace.json`.

### Удалено

- `docs/handoff/промпт-новая-сессия.md` — внутренний артефакт разработки (перенос между сессиями), не для пользователей; засорял публичное лицо репозитория.

- Все ссылки на стандарты — на `github.com/zeegin/v8std/blob/main/docs/std/NNN.md`.
- References очищены от проектной специфики.
