## [0.5.1] — 2026-08-12

### Исправлено

- **🟡 `1c-metadata` → `references/metadata-full.md` — версия платформы захардкожена как факт проекта.** В таблице «Режимы работы и совместимости» `compatibilityMode` стоял `**8.3.12**` с утверждением «методы 8.3.13+ недоступны», а `configurationExtensionCompatibilityMode` — `**8.3.27**`. Это значения проекта-донора (ТОИР), но плагин заявлен **обезличенным** — для конфигурации на 8.3.27 формулировка «8.3.13+ недоступны» **ложна** и вводит в заблуждение при ревью. Значения заменены на обезличенные («см. в своём `Configuration.mdo`»), ограничение переформулировано адаптивно: недоступны методы **новее `compatibilityMode`** (истинно для любой версии проекта).

### Происхождение

Prep-правка 3-го полевого теста: целевая конфигурация-донор (ТОИР) переведена с 8.3.12 на 8.3.27. При ревизии плагина выяснилось, что единственное место с захардкоженной версией проекта-донора — справочная таблица в `metadata-full.md`; прочие упоминания `8.3.x` — корректные пороги доступности методов (напр. «Асинх/Ждать 8.3.18+»), они адаптивны и оставлены как есть. Внесено до основных кейсов по явному требованию процедуры.

## [0.5.0] — 2026-08-12

### Исправлено

- **🔴 `marketplace.json` не бампнут в 0.4.0** — версия оставалась `0.3.0`, пока `plugin.json` и `CHANGELOG` ушли на `0.4.0`. ZCode резолвит версию из `marketplace.json`, поэтому релиз 0.4.0 **не доходил до пользователей** (кэш не обновлялся, кросс-файловая секция и `validate-new-object.sh` не подгружались). Теперь `marketplace.json` синхронизирован (`0.5.0`).
- **🔴 Баг `validate-new-object.sh` X1: ложный PASS из-за `grep -c … || echo 0`.** При 0 совпадений `grep -c` печатает `0` и возвращает exit 1 → `|| echo 0` дописывает второй `0` → `fc="0\n0"` → `[[ "$fc" -eq 0 ]]` ронял syntax error, then-ветка пропускалась → X1 рапортовал «все реквизиты присутствуют» для формы, где их нет. В 0.4.0 этот баг был исправлен в блоке F3, но **выжил в блоке X1** (второе вхождение того же антипаттерна). Введён хелпер `gc()` — безопасный счётчик без `|| echo 0`.
- **🟡 `validate-new-object.sh` выбирал форму недетерминированно** (`find … | head -1`) — у документа с несколькими формами валидировалась случайная (часто не главная). Теперь проверяются **все** `Form.form` объекта (отсортированно, с префиксом имени формы в выводе).

### Добавлено

- **`validate-new-object.sh` — проверки accumulation-регистров (§6 M12):** наличие ресурсов и измерений (FAIL при отсутствии); для `Turnovers` — WARN, что `.Остатки()`/контроль отрицательных остатков невозможен (нужен Balance); для баланс-регистра с `RecordType` — подтверждение доступности `.Остатки()`. Закрывает классовую ловушку «контроль остатков на оборотном регистре».
- **`validate-new-object.sh` — X5 сканирует `ObjectModule.bsl` и `ManagerModule.bsl`** (раньше только модули форм). Запросы проведения (`Остатки`/`СрезПоследних` в `ОбработкаПроведения`) и их параметры `&X` ↔ `УстановитьПараметр` теперь проверяются по факту.
- **`1c-events-transactions` — секция «Контроль отрицательных остатков при проведении»:** канонический паттерн `Движения.Записать()` → `Остатки(&МоментВремени, …)` → `Отказ` с требованием **баланс-регистра** (на `Turnovers` `.Остатки()` не компилируется). Образец — `ВнутреннееПотреблениеТоваров`.
- **`1c-dispatch-gate` — гейт-строка «Контроль остатков»:** маршрут «контроль остатков / `Остатки()` / проведение по остаткам» → `1c-events-transactions` + `registers-design §1`, с явным предупреждением о типе регистра.
- **`scripts/bump-version.sh`** — атомарный бамп версии сразу в `plugin.json` + `marketplace.json` (предотвращает повторение инцидента F1 с рассинхроном файлов).

### Изменено

- **`1c-events-transactions` + `1c-thin-triggers` — явное исключение №783 для контроля остатков.** Триггер «чтение внутри транзакции» больше не провоцирует «починку» выносом чтения `Остатки()` за транзакцию проведения (что сломало бы контроль). Каноничный контроль после `Движения.Записать()` явно благословлён как исключение.
- **`metadata-xml.md` §1 (LineNumber) — разделены EDT и Конфигуратор.** Прежняя формулировка «явный `LineNumber` вызывает ошибку загрузки» была категорична для EDT: реальные EDT-`.mdo` содержат его и грузятся без ошибок. Теперь: для Конфигуратора — не добавлять; для EDT — допустим, зеркалировать образец. §6 M8 смягчён соответственно.

### Происхождение изменений

Второе полевое тестирование плагина на задаче класса «проведение документа + движения по регистрам» (создание баланс-регистра и документа с контролем остатков). Главные уроки:

1. **Релиз 0.4.0 не дошёл до пользователя** из-за забытого `marketplace.json` — выявлено на ШАГЕ 0 (кэш застрял на 0.3.0).
2. **Скрипт давал ложный PASS** по багу `|| echo 0` ( второе, пропущенное в 0.4.0 вхождение того же антипаттерна) + выбирал не ту форму.
3. **Контроль остатков оказался не описан** в `1c-events-transactions`, а требование «нужен баланс-регистр, не оборотный» не звучало ни в gate, ни в events — автор едва не реализовал «остатки» на `Turnovers`.
4. **Правило LineNumber противоречило реальным EDT-файлам** проекта-донора.

Все девять отклонений (F1–F9) исправлены; скрипт перепроверен на реальных объектах (`9 PASS/0 FAIL` для регистра, `12 PASS/0 FAIL` для документа).

## [0.4.0] — 2026-08-12

### Добавлено

- **Кросс-файловая согласованность** — новый раздел в скиле `1c-thin-triggers` и `1c-metadata` → `references/metadata-xml.md` (§7): проверки связей имён между `.mdo`, `Form.form`, `Module.bsl`. Закрывает класс багов ручной правки XML, который **не ловили** чек-листы §6 (они проверяли каждый файл отдельно, а не связи между ними). Триггеры: реквизит объекта ↔ `dataPath` ↔ `Объект.X`; команда ↔ `handler` ↔ процедура; параметры запроса `&X` ↔ `УстановитьПараметр`; наличие в `Configuration.mdo`, ролях (№532), подсистеме.
- **`scripts/validate-new-object.sh`** — bash-скрипт автоматической проверки нового объекта метаданных: прогоняет §6 (дубликаты UUID/ID, companions, DataPath) + §7 (X1–X7: кросс-файловая согласованность, `Configuration.mdo`, №532, подсистема). Выводит отчёт PASS/FAIL. Не заменяет EDT-валидацию, ловит ~80% типовых багов ручной правки.

### Изменено

- **`1c-forms` + `1c-metadata` → `module-templates.md`** — уточнение: форма **без табличных частей** содержит **4 области** (область таблицы опускается; создавать «пустую» область таблицы без суффикса `<ИмяТаблицы>` нельзя — суффикс обязан соответствовать реальной ТЧ). Раньше формулировка «5 областей, даже пустые» создавала неоднозначность.
- **`1c-metadata`** — правило 12 (UUID) дополнено: сверять не только дубликаты (`uniq -d`), но и **ожидаемое количество** UUID в файле (ловит пропуски — UUID сгенерирован, но не попал в файл).
- **`1c-metadata`** — новое предупреждение **«Образец может быть с изъяном»**: при копировании структуры с существующего объекта не доверять образцу как эталону полноты (роли, подсистема, `Configuration.mdo` у образца могут отсутствовать). Проверять новый объект по чек-листу, не по образцу.

### Происхождение изменений

Предложение возникло из **полевого тестирования плагина** на реальной задаче 1С (создание обработки выгрузки справочника в JSON). В ходе работы два runtime-блокера:

1. несоответствие имени параметра запроса (`ВключатьПомеченные` ↔ `ВключаяПомеченные`);
2. расхождение имени реквизита `Включать`/`Включая` между `.mdo` и `Module.bsl` (`Объект.ВключаяПомеченныеНаУдаление` ↔ реквизит `ВключатьПомеченныеНаУдаление`);

— были пойманы **только** ad-hoc grep-сверками автора, а не встроенными чек-листами плагина. Этот PR добавляет класс кросс-файловых проверок в набор и автоматизирует скриптом. Сам скрипт в ходе разработки прошёл цикл dogfooding: первый прогон выявил 3 бага в нём самом (некорректный `|| echo 0`, ложное срабатывание на директивах `&НаКлиенте`/`&НаСервере`, неверный regex для типов полей EDT) — все исправлены до коммита.

## [0.3.0] — 2026-08-11

Третий релиз: закрыт главный пробел набора — **тестирование**. Разведка репозитория [Desko77/claude-code-skills-1c](https://github.com/Desko77/claude-code-skills-1c) (MIT) показала, что v8std не выделяет тестирование как стандарт — это ниша инструментов (YaXUnit, Vanessa Automation). Добавлен скил по практике этих инструментов; заимствованы идеи и шаблоны (аттрибуция в карточке).

### Добавлено

- **Новый скил `1c-testing`** (22-й по счёту) + `references/testing-full.md`:
  - **YaXUnit** — unit-тесты серверной бизнес-логики: шаблон `Тест<Функция>_<Сценарий>`, assertion API `ЮТест.ОжидаетЧто(...).Равно(...)`, примеры happy path и error case.
  - **Vanessa Automation** — BDD-сценарии на Gherkin (`Функционал:`/`Сценарий:`/`Дано`/`Когда`/`Тогда`), критерий выбора BDD vs unit.
  - **Типология кейсов** — 4 типа на каждую функцию: happy / edge / error / boundary.
  - **Цели покрытия** — таблица (экспортные функции 100%, бизнес-логика 90%, утилиты 80%, UI 70%, общее 80%).
  - **Arrange/Act/Assert** как главное правило структуры любого теста.
- **`1c-dispatch-gate`** — добавлена маршрутизация на `1c-testing`: новая строка в гейт-чек-листе (§1) и в таблице A по типу работы (§2).

### Изменено

- **`1c-extensions` → `references/extensions-cfe.md`** усилен двумя граблями ролей расширения (платформа 8.3.27+), заимствованными из [Desko77/1c-extension-patterns](https://github.com/Desko77/claude-code-skills-1c/blob/main/rules/1c-extension-patterns.md) (MIT):
  - **`Enum.*` в `Rights.xml`** ломает `LoadConfigFromFiles -Extension` на 8.3.27; EDT 2026.1 может генерировать такие записи сам — проверяйте `git diff` и вычищайте.
  - **Двухпроходная загрузка роли** — если в одном экспорте новые объекты + роли на них, загрузка может зависать на резолве прав; обход: первый проход без `Roles/`, второй — полностью.
- **README** — счётчик скилов 21 → 22, references 28 → 29; `1c-testing` добавлен в категорию «💻 Код».

### Честно о разведке

Изначальная разведка двух репозиториев (Desko77 и Arman-Kudaibergenov) объявила «3 темы-пробела»: тестирование, асинх/Ждать, CFE-паттерны. При проверке наших карточек выяснилось, что **асинх (`1c-async`, 209 строк) и CFE (`1c-extensions`, 223 строки) уже полностью покрыты** — разведка опиралась на обзор агента без сверки с нашими файлами. Реальный пробел остался один — тестирование. В этот релиз вошёл только он плюс 2 точечные грабли в extensions.

## [0.2.1] — 2026-07-26

Усиление `1c-code-review` по образу плагина [Unica](https://github.com/IngvarConsulting/unica) (Ingvar Consulting, LGPL-3.0). Идеи рубрикатора high-risk patterns и формата вывода ревью адаптированы под структуру v8std; контент оригинальный.

### Добавлено

- **`1c-code-review` → секция 8 «High-risk patterns»** — рубрикатор из 9 категорий, которые проверяются всегда, независимо от типа изменённого объекта (границы транзакций, запрос в цикле, контекст сервер/клиент, привилегированный режим, избыточные права, фоновые задания, внешние вызовы, временные файлы, молчаливый перехват). Каждая категория связана со стандартом v8std и с раскрытием в секциях 1–7.

### Изменено

- **`1c-code-review` → «Шаблон комментария к MR»** переработан:
  - зафиксированы принципы вывода: findings first, отсортированы по серьёзности; «не переписывай код во время ревью, если не попросили»; каждое замечание заземлено в путь+строку;
  - структура одного finding — 5 полей: `Severity · Стандарт · Path · Issue · Impact · Fix`;
  - расширенный пример сгруппированного вывода (блокирующие/важно/рекомендации + открытые вопросы + краткое резюме).

## [0.2.0] — 2026-07-25

Второй релиз: зрелость open-source + инструментирование. validate_skills.py научился видеть ссылки «наружу» (вскрыл ~60 мест проектной специфики ТОИР в карточках); добавлены тесты, CI, CONTRIBUTING. Карточки полностью обезличены до универсального состояния.

### Добавлено

- `scripts/validate_skills.py` — автопроверка структуры скилов (без зависимостей, только stdlib). Проверяет: frontmatter, `name`=каталог + kebab-case + префикс `1c-`, `description` ≤1024 (warn >250), `license: MIT`, тело ≤500 строк, отсутствие проектной специфики (`торо_`/`гкс_`/`Project/Toir`), наличие ссылок на `references/*.md` с учётом cross-skill **и** относительных markdown-ссылок «наружу» (в `std/` и cross-skill между карточками) с умным 3-уровневым резолвингом. Exit code: 0/1.
- `tests/` — юнит-тесты валидатора на stdlib `unittest`: 3 fixture-скила (эталон/сломанный/без-license) + интеграционный тест на реальных `skills/` (11 тестов, ~0.04 с).
- `.github/workflows/validate.yml` — CI на push/PR: гоняет валидатор и тесты (Python 3.11 на ubuntu-latest). Битая структура не попадёт в `main`.
- `CONTRIBUTING.md` — гайд для контрибьюторов: как добавить скил, правила оформления (универсальность, ссылки, версии), синхронизация с upstream.
- `.github/PULL_REQUEST_TEMPLATE.md` — чек-лист PR (CI зелёный, локальная проверка, универсальность, README/CHANGELOG обновлены).
- `.github/ISSUE_TEMPLATE/` — шаблоны `bug_report.yml` (under/over-trigger, устаревшее правило, битая ссылка) и `feature_request.yml` + `config.yml` (вопросы → Discussions).
- `SECURITY.md` — политика безопасности (поверхность атаки минимальна: нет рантайм-кода, только `.md` и CI-линтер; ответственное раскрытие через e-mail).

### Особенности

- Все ссылки на стандарты — на `github.com/zeegin/v8std/blob/main/docs/std/NNN.md`.
- References очищены от проектной специфики.
